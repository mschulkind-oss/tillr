# Cancelling the tip-watcher during an automatic revert never orphans `packed-refs.lock`

**Status:** 2026-11-26, verified against `1eeef862a070`. Not built: `rg -n 'holdsGitLocks|onRevertWatchCanceled' tools/tillr-drain` returns nothing, `GitOutput` in [`tools/tillr-drain/heavy/status.go`](../../tools/tillr-drain/heavy/status.go) runs every Git command through `exec.CommandContext`, and `detachedWorktreeAt` in [`tools/tillr-drain/drain/steps.go`](../../tools/tillr-drain/drain/steps.go) runs `exec.CommandContext(ctx, "git", "-C", s.Root, "worktree", "add", "--detach", "--force", dir, rev)`. Following owner ruling [`R-NOQ1`](./no-open-questions-in-references.md#R-NOQ1), this unbuilt specification lives in a standalone design document under `docs/design/` linking [`docs/reference/gate.md`](../reference/gate.md) rather than adding an unbuilt decision to [`docs/reference/gate.md`](../reference/gate.md). Decisions [`D-HRPL1`](#D-HRPL1) (superseded) and [`D-HRPL2`](#D-HRPL2) in the [Decision Ledger](#4-decision-ledger) are **the designer's decisions answering a 2026-11-26 filed operator request and its build-seat conflict — never owner rulings — and the owner may overturn any part of them**.

> **In short.** `TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed` failed on 2026-11-26 because `cancelWatch()` in `revertLanding` cancelled `watchCtx` while the `watchWG` tip-watcher goroutine was running `git checkout --force --detach` (or `git reset --hard` / `git worktree add --detach`), orphaning `<root>/.git/packed-refs.lock` on disk before `watchWG.Wait()` returned so `land.Land`'s `git update-ref -d refs/tillr/trunk-history/lost` later failed with `File exists`. Superseded [`D-HRPL1`](#D-HRPL1) replaced `SIGKILL` with `SIGTERM`, which still failed `3/50` runs under `-race`: in Git `2.56.0`'s `repo_create_tempfile_mode`, `open64` creates the `0`-byte `.lock` file in the kernel *before* user-space links the entry onto `tempfile_list` and sets `owner = getpid()`, so `SIGTERM` delivered at syscall return exits via `remove_tempfiles_on_signal` without unlinking `packed-refs.lock`. [`D-HRPL2`](#D-HRPL2) extends the pattern landed in `03abd315` (`(*Loop).git`): refuse to start lock-acquiring local `git` commands once `ctx.Err() != nil`, and run an already-started one with `exec.Command` so it finishes its `~1–5 ms` local transaction and unlinks `.lock` files cleanly before `watchWG.Wait()` returns, with zero retries.

**Why it matters.** Orphaning `<root>/.git/packed-refs.lock` when `cancelWatch()` stops `watchWG` turns a valid automatic revert ([`D-GR6`](../reference/gate.md#D-GR6)) into `result: "not-possible"` (`the lander could not land the revert`), filing an unnecessary trunk fixer in production and flaking `go-test-tillr-drain` under load ([§1](#1-forensics-of-the-2026-11-26-failure-and-why-sigterm-still-orphans-packed-refslock)).

**The shape.** Classify lock-acquiring local Git subcommands in `heavy.GitOutput` ([`tools/tillr-drain/heavy/status.go`](../../tools/tillr-drain/heavy/status.go)) and `detachedWorktreeAt` ([`tools/tillr-drain/drain/steps.go`](../../tools/tillr-drain/drain/steps.go)): check `ctx.Err()` before starting them, run an already-started lock-acquiring `git` subprocess via `exec.Command` without signaling it on context cancellation, check `ctx.Err()` before `fn(r.Work)` in `HeavyRunner.inTree` ([`tools/tillr-drain/heavyrun/heavy.go`](../../tools/tillr-drain/heavyrun/heavy.go)) and after `worktree add` in `detachedWorktreeAt`, mirror via `just pack-sync`, and prove both deterministic lock release and `50/50` `-race` stability in [`tools/tillr-drain/drain/heavy_revert_tip_passes_test.go`](../../tools/tillr-drain/drain/heavy_revert_tip_passes_test.go) ([§2](#2-non-signaling-completion-for-started-lock-acquiring-git-commands-d-hrpl2)).

**Cost.** One small lock-subcommand helper in `tools/tillr-drain/heavy/status.go`, matching `ctx.Err()` guards and `exec.Command` in `detachedWorktreeAt` (`tools/tillr-drain/drain/steps.go`) and `HeavyRunner.inTree` (`tools/tillr-drain/heavyrun/heavy.go`), one optional package-private test callback on `Loop` (`tools/tillr-drain/drain/loop.go`, `tools/tillr-drain/drain/heavy_revert.go`), `just pack-sync`, and one deterministic FIFO-synchronized regression test (`zero` retries).

**Start at [§1](#1-forensics-of-the-2026-11-26-failure-and-why-sigterm-still-orphans-packed-refslock)** for the original root cause plus the Git `2.56.0` `repo_create_tempfile_mode` assembly window that broke `SIGTERM` under `-race`, and [§2](#2-non-signaling-completion-for-started-lock-acquiring-git-commands-d-hrpl2) for [`D-HRPL2`](#D-HRPL2).

## 1. Forensics of the 2026-11-26 Failure and Why `SIGTERM` Still Orphans `packed-refs.lock`

### 1.1 What failed on 2026-11-26 and why the request inferred two concurrent commands

On 2026-11-26 at ~03:15 ET (load average near `110`), the after-merge trunk proof's `go-test-tillr-drain` check failed once in `TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed` ([`tools/tillr-drain/drain/heavy_revert_tip_passes_test.go`](../../tools/tillr-drain/drain/heavy_revert_tip_passes_test.go), added in `b1809482`). Instead of recording one `drain.revert` event with `result: "reverted"`, `revertLanding` recorded `result: "not-possible"` with:

```text
the lander could not land the revert: error: Unable to create '<fixture>/.git/packed-refs.lock': File exists.
Another git process seems to be running in this repository, or the lock file may be stale
```

Git's `unable_to_lock_message()` prints that identical two-part message whenever `open("<path>.lock", O_RDWR|O_CREAT|O_EXCL)` fails with `EEXIST` — both when another live Git process holds the lock and when an earlier killed Git process left a stale `.lock` file behind. Reading the first half of Git's message, the filed operator request inferred that a second Git command of the loop was writing refs in the fixture repository *at the same moment* the lander was landing the automatic revert, and worded custom Criteria 5 and 6 around two Git commands running at once during `land.Land`.

### 1.2 The two colliding Git commands in the repository

Tracing [`revertLanding`](../../tools/tillr-drain/drain/heavy_revert.go) and running `/bin/git` `2.56.0` under `strace -f -e trace=openat,unlink,unlinkat,rename,rt_sigaction` on 2026-11-26 establishes the exact two Git operations of the loop that collided over `<root>/.git/packed-refs.lock`:

1. **`watchWG` exits before post-gate `replay` and `land.Land` start.** In `revertLanding` ([`tools/tillr-drain/drain/heavy_revert.go`](../../tools/tillr-drain/drain/heavy_revert.go)), `cancelWatch()` and `watchWG.Wait()` run immediately after `l.cfg.Steps.Gate(gateCtx, candidate)` returns, strictly before post-gate `replay(ctx, revert, id)` and `l.landWithActions(ctx, candidate)` (`land.Land`) execute. Because `cmd.CombinedOutput()` waits for its child `git` process to exit before `watchWG.Done()` runs, **no second Git process is running concurrently when `land.Land` executes**.
2. **First Git command (`watchWG` killed mid-lockfile while touching `<root>/.git/packed-refs.lock`).** While `Steps.Gate` runs on `.revert/worktree`, `revertLanding`'s `watchWG` goroutine polls `l.trunkRef()` under `watchCtx`. When the trunk tip moves (`h.landRemoval("item-partial", "a")` in `TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed`, or a concurrent landing on `main` in the live loop), `watchWG` calls `tipChecksPass(watchCtx, cur, ids, replay)` -> `HeavyRunner.one` -> `HeavyRunner.OneLogged` -> `HeavyRunner.inTree` -> `tryReuseProofWorktree(watchCtx, r.Work, tip)` in [`tools/tillr-drain/heavyrun/heavy.go`](../../tools/tillr-drain/heavyrun/heavy.go) (or the fallback `worktree remove` / `worktree add --detach` in `inTree`; and on the `revertFromGateReplay` path, `ProcessSteps.Replay` -> `replayWorktree` -> `detachedWorktree` -> `detachedWorktreeAt` in [`tools/tillr-drain/drain/steps.go`](../../tools/tillr-drain/drain/steps.go)).
   - Measured with `strace -f -e trace=openat` against `/bin/git` `2.56.0` on 2026-11-26: in a linked worktree, `git checkout -q --force --detach <sha>`, `git reset -q --hard <sha>`, and `git worktree add -q --detach`'s child `git` each delete the worktree's `AUTO_MERGE` pseudoref twice through Git's ref-transaction layer, opening `<common-git-dir>/packed-refs.lock` with `O_RDWR|O_CREAT|O_EXCL|O_CLOEXEC` twice per command (alongside worktree `.lock` files `index.lock`, `HEAD.lock`, `ORIG_HEAD.lock`, and `AUTO_MERGE.lock`), whereas `rev-parse`, `clean -ffdx`, `branch --show-current`, and `--no-optional-locks status` open zero `.lock` files.
   - In `TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed`, `"unit-a"` passes on `partial`, so `tipChecksPass` advances to `"unit-b"` and enters `tryReuseProofWorktree` a second time. When `Steps.Gate` finishes its `80ms` wait while `watchWG` is inside `checkout --force --detach` or `reset --hard` (or `worktree add --detach`), `revertLanding` calls `cancelWatch()`. With `exec.CommandContext`'s default `SIGKILL`, Go kills `git` immediately and leaves `<root>/.git/packed-refs.lock` orphaned on disk.
3. **Second Git command (`land.Land` refused by the orphaned `<root>/.git/packed-refs.lock`).** After `watchWG.Wait()` returns, intermediate `checkout --force --detach` and `reset --hard` calls in post-gate `replay` and pre-land `tipChecksPass` hit the stale `<root>/.git/packed-refs.lock` on their non-fatal `AUTO_MERGE` deletes (waiting `core.packedRefsTimeout` = `1,000 ms` per lock attempt and still exiting `0`). Then `l.landWithActions(ctx, candidate)` calls `land.Land` -> `dropLostHistoryRef` ([`tools/tillr-land/land/trunk_history.go`](../../tools/tillr-land/land/trunk_history.go)), which runs `git -C <root> update-ref -d refs/tillr/trunk-history/lost`. Deleting a ref requires `<root>/.git/packed-refs.lock`, waits `1,000 ms`, and exits `1` with `Unable to create '<fixture>/.git/packed-refs.lock': File exists`, causing `revertLanding` to record `result: "not-possible"` instead of `"reverted"`.

### 1.3 Why [`D-HRPL1`](#D-HRPL1)'s `SIGTERM` cancellation still failed `3/50` under `-race` in Git `2.56.0`

[`D-HRPL1`](#D-HRPL1) (landed in `632801a382a2`) assumed that replacing `SIGKILL` with process-group `SIGTERM` + `5s` `WaitDelay` would always let Git's `tempfile.c` signal handler unlink `<root>/.git/packed-refs.lock` before `git` exited. On 2026-11-26, implementing [`D-HRPL1`](#D-HRPL1) passed the FIFO test paused at `update-ref --stdin`'s `prepare: ok`, **but failed `3/50` times** under `go test -race -count=50 -run '^TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed$' ./drain` with `Unable to create '<fixture>/.git/packed-refs.lock': File exists`. Diagnostic runs confirmed twice that `git checkout --force --detach <sha>` received `SIGTERM` (`killErr=<nil>`), exited with `signal: terminated` (not `SIGKILL`/`WaitDelay`), and still left a `0`-byte `<root>/.git/packed-refs.lock` on disk immediately after `watchWG.Wait()` returned.

Disassembling `/bin/git` (`git version 2.56.0`) with `objdump -d /bin/git` around `repo_create_tempfile_mode`, `remove_tempfiles_on_signal`, and `remove_tempfiles` on 2026-11-26 proves why `SIGTERM` is unsafe:

1. Earlier in `git checkout --force --detach <sha>`, locking `index.lock` sets `initialized.1 = 1` and installs `remove_tempfiles_on_signal` on `SIGINT`, `SIGHUP`, `SIGTERM`, `SIGQUIT`, and `SIGPIPE`.
2. Later in the same `git` process, deleting `AUTO_MERGE` calls `repo_create_tempfile_mode` for `<common-git-dir>/packed-refs.lock`. In `/bin/git` `2.56.0`, `repo_create_tempfile_mode` executes in this exact order:
   - Calls `open64(tempfile->filename.buf, O_RDWR|O_CREAT|O_EXCL|O_CLOEXEC, mode)` (`$0x800c2`), creating the `0`-byte `<common-git-dir>/packed-refs.lock` file in the kernel **before** `tempfile` is on `tempfile_list` and while `tempfile->owner` is still `0`.
   - Only **after** `open64` returns a non-negative descriptor to user-space does `repo_create_tempfile_mode` splice `tempfile` into `tempfile_list` and call `getpid()` to store `tempfile->owner = getpid()`.
3. Meanwhile, `remove_tempfiles` (called by `remove_tempfiles_on_signal`) walks `tempfile_list` and skips any node not yet linked or whose `tempfile->owner != getpid()`, then `remove_tempfiles_on_signal` calls `sigchain_pop(SIGTERM)` and `raise(SIGTERM)`.
4. Whenever `cancelWatch()` sends `SIGTERM` while `git` is inside `open64(".../packed-refs.lock", ...)` (or in user-space before `tempfile_list` insertion and `tempfile->owner = getpid()` complete), the Linux kernel delivers `SIGTERM` on syscall return **before** user-space executes `activate_tempfile`: `remove_tempfiles_on_signal` unlinks `AUTO_MERGE.lock`, cannot see `packed-refs.lock`, and terminates `git` (`signal: terminated`) leaving a `0`-byte `packed-refs.lock` orphaned on disk.

Consequently, **no asynchronous signal (`SIGKILL` or `SIGTERM`) can safely interrupt an in-flight lock-acquiring Git subprocess without a kernel-to-userspace lockfile-orphan window**. Commit `03abd315` already solved the sibling `observed.lock` bug in `(*Loop).git` ([`tools/tillr-drain/drain/loop.go`](../../tools/tillr-drain/drain/loop.go)) by checking `ctx.Err()` before starting `git update-ref` and running an already-started `git update-ref` via `exec.Command` so it finishes cleanly without receiving a signal.

## 2. Non-Signaling Completion for Started Lock-Acquiring Git Commands ([`D-HRPL2`](#D-HRPL2))

*Designer's decision answering the 2026-11-26 build conflict on [`D-HRPL1`](#D-HRPL1) from a filed operator request — not an owner ruling — which the owner may overturn.*

### 2.1 Refuse to start after `ctx.Err() != nil`; let an already-started lock-acquiring `git` finish

1. **`heavy.GitOutput` in [`tools/tillr-drain/heavy/status.go`](../../tools/tillr-drain/heavy/status.go).** Add a package-private classifier `holdsGitLocks(args []string) bool` in `tools/tillr-drain/heavy/status.go` (keeping `heavy` a leaf package with zero imports from `heavyrun` or `drain` per [`D-GR47`](../reference/gate.md#D-GR47)):
   - Walk `args` past leading global Git options (two-token `-c`, `-C`, `--git-dir`, `--work-tree`, `--namespace`, `--super-prefix`, `--config-env`, and single-token `-*` flags such as `--no-optional-locks`, `-C<dir>`, `--git-dir=...`, `--work-tree=...`, stopping flag scan at `--`) to find the Git subcommand.
   - Return `true` when the subcommand is `"update-ref"`, `"checkout"`, `"reset"`, `"merge"`, `"rebase"`, `"cherry-pick"`, `"revert"`, `"commit"`, or `"worktree"` with any action (first non-flag token after `"worktree"`) other than `"list"`.
   - Return `false` for all lock-free / read-only subcommands (`rev-parse`, `show-ref`, `rev-list`, `merge-base`, `worktree list`, `branch`, `status`, `cat-file`, `show`, `diff-tree`, `diff`, `ls-tree`, `clean`). (`heavy.Green` runs only read-only `show-ref --verify` and `rev-parse` and keeps `exec.CommandContext`.)
   - In `GitOutput(ctx, root, args...)`:
     - When `holdsGitLocks(args)` is `true`, check `if err := ctx.Err(); err != nil { return "", fmt.Errorf("git %s: %w", strings.Join(args, " "), err) }` **before** starting `git`. Once started, run `exec.Command("git", append([]string{"-C", root}, args...)...)` (never `exec.CommandContext` and never `SIGTERM`/`SIGKILL` on `ctx` cancellation) so the short local Git operation (`~1–5 ms`) completes its ref/index transaction and unlinks `<common-git-dir>/packed-refs.lock` and worktree `.lock` files through Git's normal `commit_lock_file` / `delete_tempfile` path before `cmd.CombinedOutput()` returns.
     - When `holdsGitLocks(args)` is `false`, run `exec.CommandContext(ctx, "git", append([]string{"-C", root}, args...)...)`.
   - Because `cmd.CombinedOutput()` waits for that already-started `git` process to exit normally, `watchWG.Wait()` in `revertLanding` strictly orders lock release before post-gate `replay` and `land.Land` begin, and the very next step in `tryReuseProofWorktree` or `HeavyRunner.inTree` observes `watchCtx.Err() != nil` and refuses to start another mutating `git` command.
2. **`HeavyRunner.inTree` in [`tools/tillr-drain/heavyrun/heavy.go`](../../tools/tillr-drain/heavyrun/heavy.go).** Check `if err := ctx.Err(); err != nil { return err }` immediately before `return fn(r.Work)` so that if `ctx` was cancelled while the final worktree step (`tryReuseProofWorktree` or `worktree add --detach`) was completing, `inTree` returns `ctx.Err()` without invoking `Judge` on a cancelled context.
3. **`detachedWorktreeAt` in [`tools/tillr-drain/drain/steps.go`](../../tools/tillr-drain/drain/steps.go).**
   - Inside `withWorktreeRegistryLock(ctx, s.Root, ...)`: check `if err := ctx.Err(); err != nil` before `pickDir()` and again after `unlockRegisteredWorktree` (removing `dir` via `os.RemoveAll(dir)` if `pickDir()` created an empty directory before returning `err`), and replace `exec.CommandContext(ctx, "git", "-C", s.Root, "worktree", "add", "--detach", "--force", dir, rev)` with `exec.Command("git", "-C", s.Root, "worktree", "add", "--detach", "--force", dir, rev)` (matching the surrounding `exec.Command` calls for `worktree remove` and `worktree prune`) so cancelling `watchCtx` on the `revertFromGateReplay` path (`ProcessSteps.Replay` -> `replayWorktree` -> `detachedWorktree`) never signals `git worktree add` or its child `git` mid-lock.
   - Immediately after `withWorktreeRegistryLock` succeeds, check `if err := ctx.Err(); err != nil { cleanup(); return "", func() {}, err }` so a cancellation that arrived while `git worktree add` ran removes the scratch `.replay/<sha>-*` worktree cleanly under `context.Background()` and returns `ctx.Err()`.
4. **Test observation seam in `revertLanding` ([`tools/tillr-drain/drain/loop.go`](../../tools/tillr-drain/drain/loop.go), [`tools/tillr-drain/drain/heavy_revert.go`](../../tools/tillr-drain/drain/heavy_revert.go)).** Add an optional package-private `onRevertWatchCanceled func()` field on `Loop` (beside `revertTipPoll`), called in `revertLanding` immediately after `cancelWatch()` and before `watchWG.Wait()` when non-nil, so the deterministic regression test observes `cancelWatch()` before releasing the held ref transaction.
5. **Format and pack mirror.** Run `just format` and `just pack-sync` and commit the synced mirror under `yolo-packs/tillr/files/local/share/tillr/tillr-drain/` in the same commit.

### 2.2 Reading of the filed request and Criteria 5, 6, and 7

Because the filed request's saved words stay byte-for-byte unchanged in the store, both the builder and the `verify` evaluator read the request's words and Criteria 5, 6, and 7 together with [`D-HRPL2`](#D-HRPL2) as follows:

- **Criterion 5 (naming the two colliding Git commands from the code and reproduction, not guessed):** Satisfied when the commit body and regression test comment name the two Git commands established in [§1.2](#12-the-two-colliding-git-commands-in-the-repository) and [§1.3](#13-why-d-hrpl1s-sigterm-cancellation-still-failed-350-under--race-in-git-2560):
  1. `watchWG`'s `tipChecksPass` -> `tryReuseProofWorktree` `git checkout --force --detach` / `git reset --hard` (and fallback / replay `git worktree add --detach`) invoked through `heavy.GitOutput` / `detachedWorktreeAt`, which `cancelWatch()` signaled while touching `<root>/.git/packed-refs.lock` (killed immediately by `SIGKILL` under `exec.CommandContext`, and killed inside Git `2.56.0`'s `repo_create_tempfile_mode` `open64`-before-`activate_tempfile` window under `SIGTERM`); and
  2. `land.Land` (`dropLostHistoryRef`)'s `git update-ref -d refs/tillr/trunk-history/lost` in the same repository, which failed with `Unable to create '<fixture>/.git/packed-refs.lock': File exists` on that orphaned `packed-refs.lock` after `watchWG.Wait()` returned.
- **Criterion 6 (ordered at the cause so neither holds or orphans `packed-refs.lock` across `watchWG.Wait()`, with no retry and no wait-and-try-again, proved by a test that fails before the change):** Satisfied by `holdsGitLocks` + `ctx.Err()` pre-start check + non-signaling `exec.Command` in `heavy.GitOutput` and `detachedWorktreeAt` (with zero retries, zero backoff loops, and zero lockfile unlinking by Tillr) together with a deterministic FIFO-synchronized regression test in [`tools/tillr-drain/drain/heavy_revert_tip_passes_test.go`](../../tools/tillr-drain/drain/heavy_revert_tip_passes_test.go):
  - Following `TestStopMidPassWhileUpdateRefHoldsLockLeavesNextLoopClean` in [`tools/tillr-drain/drain/stop_prompt_test.go`](../../tools/tillr-drain/drain/stop_prompt_test.go), a `PATH` wrapper `git` script armed once after `h.landRemoval` intercepts `watchWG`'s `checkout` on the proof worktree and `exec`s `realGit -C <h.root> update-ref --stdin` driven to `prepare: ok` on a `delete` transaction so `realGit` holds `<h.root>/.git/packed-refs.lock`.
  - Once `prepare: ok` is observed (guarded only by `hangGuard`, never a `< 5m` failure deadline), `onGateCtx` returns `GateOutcome{Outcome: GatePassed}`, causing `revertLanding` to call `cancelWatch()`, invoke `onRevertWatchCanceled`, and wait in `watchWG.Wait()`.
  - After `onRevertWatchCanceled` fires (plus a short non-failing pause such as `25ms` so any `CommandContext` signal goroutine has delivered its signal before stdin continues), the driver sends `abort` (or `commit`) to `inFIFO` and requires `abort: ok` (or `commit: ok`) from `outFIFO`.
  - Before the change (`SIGKILL`), `realGit` is killed before `abort: ok`, `<h.root>/.git/packed-refs.lock` remains orphaned after `watchWG.Wait()`, `land.Land` fails on `packed-refs.lock`, and `h.reverts()` records `result: "not-possible"`. Under superseded [`D-HRPL1`](#D-HRPL1) (`SIGTERM`), `realGit` is also killed before `abort: ok`, failing the driver check. Under [`D-HRPL2`](#D-HRPL2), `realGit` finishes cleanly (`abort: ok`), unlinks `<h.root>/.git/packed-refs.lock`, subsequent mutating `GitOutput` calls in `watchWG` refuse to start on the cancelled `watchCtx`, `watchWG.Wait()` returns with zero `.lock` files on disk, and `h.reverts()` records one `result: "reverted"` event for `culprit`.
- **Criterion 7 (`TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed` stability under `-race`):** `go test -race -count=50 -run '^TestHeavyRevertContinuesWhenPartialRepairLeavesOneCheckRed$' ./drain` passes `50/50` because no lock-acquiring Git subprocess in `watchWG` is ever sent `SIGKILL` or `SIGTERM`.

### 2.3 Rejected alternatives

- **Process-group `SIGTERM` + `WaitDelay` on lock-acquiring Git subprocesses (superseded [`D-HRPL1`](#D-HRPL1)):** Fails `3/50` under `-race` on Git `2.56.0` because `repo_create_tempfile_mode` creates `<path>.lock` in `open64` before `activate_tempfile` registers it on `tempfile_list` with `owner = getpid()` ([§1.3](#13-why-d-hrpl1s-sigterm-cancellation-still-failed-350-under--race-in-git-2560)).
- **Adding a short kill timeout / `WaitDelay` timer to started local lock-acquiring Git commands:** Any asynchronous signal timer reintroduces the exact `repo_create_tempfile_mode` orphan window under extreme machine load (`load ~110`) and violates [`D-GR15`](../reference/gate.md#why-its-this-way) ([§8](./landing-principles.md#8-a-gate-that-cannot-answer-must-say-which)); commit `03abd315` already runs started local `git update-ref` without a kill timer in `(*Loop).git`.
- **Retrying or sleeping-and-retrying on `packed-refs.lock` in `tillr-land` or `revertLanding`:** Forbidden by the request (`"A flake is a defect: find the cause, do not add a retry"`) and [§11](./landing-principles.md#11-a-failure-is-diagnosed-not-waited-out), and useless against an orphaned `packed-refs.lock` that never clears on its own.
- **Having Tillr `os.Remove` `<root>/.git/packed-refs.lock`:** Unsafe — Tillr cannot distinguish an orphaned `packed-refs.lock` from a live ref transaction held by a concurrent `tillr-land` or `git` process in the same repository.
- **Adding an in-process Go mutex around Git calls while still signaling `git` on `watchCtx` cancellation:** Still orphans `packed-refs.lock` on disk whenever a lock-acquiring `git` subprocess receives `SIGKILL` or `SIGTERM`.
- **Running every `heavy.GitOutput` command with uncancellable `exec.Command` without checking `ctx.Err()` before start:** Without the pre-start `ctx.Err()` check, `tryReuseProofWorktree` would keep launching the remaining `git` commands in its sequence after `cancelWatch()` fired; checking `ctx.Err()` before start stops at most after the single `~1–5 ms` in-flight command completes, while keeping read-only queries cancellable via `exec.CommandContext`.
- **Importing `heavyrun` or `drain` into `heavy`:** Violates [`D-GR47`](../reference/gate.md#D-GR47), under which `heavy` stays a leaf package imported by `view`, `heavyrun`, and `drain`.
