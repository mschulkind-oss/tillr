# Breaking `tools/tillr-drain/drain` into single-job internal packages via conflict-free extractions

**Status:** Waves 1–3 landed: Wave 1 (`E01`: `tools/tillr-drain/internal/drainmodel/`, `tools/tillr-drain/architecture_test.go`, and `CheckDrainTestParity` in `tools/tillr-gate/goaffected/parity.go`) in commit `59c72862`, Wave 2 (`E02`: `internal/procguard/` in `ab7bf375`; `E03`: `internal/boundary/` in `e60c543a`; `E04`: `internal/storelog/` in `c7c6a8a1`), and Wave 3 (`E05`: `internal/runhistory/` in `a9e77e15`; baseline coupling inventory measured at `0e57a73d` on 2026-11-25); `E06`–`E22` are not yet built (`fd --max-depth 1 --type d . tools/tillr-drain/internal | sort` at `6888ca2c` returns `tools/tillr-drain/internal/boundary/`, `tools/tillr-drain/internal/drainmodel/`, `tools/tillr-drain/internal/procguard/`, `tools/tillr-drain/internal/runhistory/`, `tools/tillr-drain/internal/storelog/`, and `tools/tillr-drain/internal/testinputs/`). `R-DPD1` ([§1.1](#11-owner-direction-and-standing-rules)) records the owner's verbatim 2026-11-25 direction. Every structural choice and 2026-11-26 `E01`/`E03`/`E04`/`E05`/`E06`/`E07` boundary amendment in this document — [`D-DPD1`](#D-DPD1) through [`D-DPD14`](#D-DPD14) in the [Decision Ledger](#decision-ledger) — is **the designer's decision, open to the owner to overturn**. [`OQ-DPD1`](#OQ-DPD1) asks the owner how pre-merge `go-affected` treats the three extracted packages whose subprocess test suites exceed `25 s` serial alongside [`OQ-DFG1`](./fast-gate-tillr-drain-options.md#OQ-DFG1).

> **In short.** At the `0e57a73d` coupling inventory (`259` `.go` files / `603` `*_test.go` files / `150` `Loop` fields / `25` mutexes by `be08e50b`, and `159` `Loop` fields / `26` mutexes seeded in `E01` at `59c72862`), `tools/tillr-drain/drain` compiled **`251` production `.go` files (`87,692` lines)** and **`585` `*_test.go` files (`137,122` lines; `224,814` total lines, `2,125` executable `Test*` functions, `3,636.34 s` recorded duration)** into one Go package where `struct Loop` carried **`146` fields and `24` `sync.Mutex`/`sync.RWMutex` locks**. Over half of `Loop`'s **`761` methods (`382`, `50.2%`)** never touch mutable loop state — they take `(l *Loop)` only to reach `l.cfg.Store`, `l.cfg.Root`, `l.cfg.Now`, `l.git`, `l.reportf`, `Candidate`, or `Decision` — while **`1,042` of `2,125` `Test*` functions (`49.0%`, `512.36 s`)** never run a `Loop` pass or spawn the `tillr-drain` binary. This design extracts **`228` production files (`72,084` lines, `82.2%`)** and **`150` whole test files (`422` `Test*` functions, `240.50 s`)** into **`22` single-job packages under `tools/tillr-drain/internal/`** in a strict 6-layer DAG (`D-DPD1`–`D-DPD3`, `D-DPD9`–`D-DPD14`), leaves only the **pass/examination/restart coordinator** in `drain` (`D-DPD4`), lands the move in **`22` single-commit queue items across `13` file-disjoint waves** while ordinary `drain` work and `just pack-sync` continue (`D-DPD5`–`D-DPD7`), and prevents coupling from returning with an automated `< 0.2 s` pre-merge architecture check extending [`D-GR47`](../reference/gate.md#D-GR47) (`D-DPD8`).

**Why it matters.** Because all `drain` production and test files share one Go package namespace:
- Editing any helper in `drain` recompiles `224,814` lines and invalidates Go's per-binary test cache across all `2,125` tests (`3,636.34 s` in [`tools/go-test-durations.json`](../../tools/go-test-durations.json)).
- Under [`D-GR54`](../reference/gate.md#D-GR54) (`DeferredProofPackages` in [`tools/tillr-gate/goaffected/select.go`](../../tools/tillr-gate/goaffected/select.go) deferring `tillr-drain/drain` to after-merge `go-test-tillr-drain`), subsystem logic trapped inside `package drain` gets **`0` tests of its own behavior before the merge** when its source changes, whereas loop-free subpackages run their own fast cached suites before the merge.
- Subsystem state and locks (`24` mutexes across policy, quotas, CPU accounting, lane rotation, heavy proof, trunk locks, WAL checkpoints, and fast-start views) sit exposed on `struct Loop`, allowing cross-domain field reads and lock-order hazards across `475` white-box test files and `166` production files.

## 1. Measured Baseline: What `drain` Holds Today and How It Couples

### 1.1 Owner direction and standing rules

One dated verbatim statement by the owner sets the goal of this design:

- **`R-DPD1` (2026-11-25, owner):** *"Surely there's a better architecture here. This like interconnected mess of stuff is not good for development speed, it's not good for testing, it's not good for development in general, bugs"*

The owner left the choice of architecture to the designer and asked for a sequence of separately landed extraction items rather than a big-bang rewrite that would collide with active lanes. No other statement in this document is attributed to the owner; every package boundary, layer rule, seam interface, wave dependency, and gate check below (`D-DPD1`–`D-DPD14`) is **the designer's decision, open to the owner to overturn**.

Four standing repository rules bound the design:

1. **Loop-free subpackages never import `drain` ([`D-GR47`](../reference/gate.md#D-GR47)).** Subpackages under `tools/tillr-drain/` that do not run `drain.Loop` never import `github.com/mschulkind-oss/tillr-drain/drain` or the root `github.com/mschulkind-oss/tillr-drain` package in production or test code, and extractions prove isolation and zero dropped tests deterministically rather than by wall-clock timing thresholds.
2. **Pre-merge vs. after-merge Go test split ([`D-GR53`](../reference/gate.md#D-GR53), [`D-GR54`](../reference/gate.md#D-GR54), [`D-GR56`](../reference/gate.md#D-GR56), [`OQ-DFG1`](./fast-gate-tillr-drain-options.md#OQ-DFG1)).** Following commits `5e728e5a`, `bc431c25`, and `1eeef862` (which ported the Python gate runners to Go under [`tools/tillr-gate/goaffected/`](../../tools/tillr-gate/goaffected/) and removed all `.py` gate scripts under [`tools/gate/no_python.go`](../../tools/gate/no_python.go)), `DeferredProofPackages` in [`tools/tillr-gate/goaffected/select.go`](../../tools/tillr-gate/goaffected/select.go) defers only `github.com/mschulkind-oss/tillr-drain/drain` to after-merge `go-test-tillr-drain`, while `go-build` compiles all `tools/tillr-drain/...` code and tests before the merge and `go-affected` runs all other `tools/tillr-drain` subpackages and consumer modules before the merge.
3. **External Go callers of `tillr-drain/drain`.** Outside `tools/tillr-drain/drain`, three packages import `github.com/mschulkind-oss/tillr-drain/drain`: root `tools/tillr-drain` (`main.go` and CLI subcommands), `tools/tillr-store` (event payload readers), and `tools/tillr-watch` (watch event schemas). Preserving `drain`'s exported entrypoints and type aliases avoids cross-module churn during internal extractions.
4. **Shipped module mirror (`pack-sync`) and candidate size.** [`tools/tillr/packsync/packsync.go`](../../tools/tillr/packsync/packsync.go) (`CaseTreeMatchesSource`) skips generated mirror checks on `--candidate` runs while [`tools/tillr-drain/internal/boundary/pack_mirror.go`](../../tools/tillr-drain/internal/boundary/pack_mirror.go) (`StagePackMirror` and `FilterMirrorConflictReports`, bridged in `drain/boundary_bridge.go`) renders `yolo-packs/tillr/files/local/share/tillr/tillr-drain/` 1-to-1 per source path at landing. [`.tillr.toml`](../../.tillr.toml) sets advisory `[candidate_size]` thresholds of `file_limit = 27` and `added_line_limit = 1200` (measured by `measureCandidateSize` in `candidate_size.go` with `git diff --numstat -z --find-renames` excluding `yolo-packs/tillr/files/local/share/tillr/`).

## 2. Target Architecture: Single-Job Packages, Layer DAG, and Seam Interfaces

### 2.1 Module-private `internal/` namespace and stable `drain` bridge (`D-DPD1`)

**Designer's decision (`D-DPD1`); the owner may overturn it.** All `22` extracted packages live under `tools/tillr-drain/internal/<pkg>` (`github.com/mschulkind-oss/tillr-drain/internal/<pkg>`), while:
1. The existing non-`drain` leaf packages (`21` at `0e57a73d`, `25` at `be08e50b`: `alarms`, `faults`, `fixer`, `forkgate`, `heavy`, `heavyrun`, `holdrules`, `keep`, `lanestate`, `obstacles`, `ownercriteria`, `patchmoves`, `presence`, `preserved`, `quota`, `redcap`, `remotesync`, `restart`, `spend`, `stop`, `workflow`, plus earlier leaf helpers) remain at **Layer `-1`** (public module leaf contracts that import neither `drain` nor `internal/*`, unless a leaf contract itself is consumed downward by `internal/*`).

**Designer's decision (`D-DPD3`); the owner may overturn it.** Instead of passing `*Loop` into `166` files (`382` stateless `cfg`/logger methods + `379` stateful methods), subsystems depend on seven small interfaces and value structs defined at the consuming layer:

// Layer 2 (internal/steps): existing 6-method Steps seam (Run, Gate, Land, Verdict, ItemState, Sync),

`struct Loop` shrinks from **`150` fields and `25` mutexes** at `be08e50b` (`146` fields and `24` mutexes at `0e57a73d`) to **`<= 45` fields and `<= 8` mutexes** (`mu`, `restartMu`, `restartMechanical`, `restartGateMu`, `pollReaderMu`, `restartPollMu`, `sessionMu`, `reportMu`), holding subsystem pointers (`proc *procguard.Guard`, `store *storelog.Writer`, `policy *policy.Runtime`, `lanes *lanepool.Pool`, `trunk *trunkland.Coordinator`, `heavy *heavyproof.Coordinator`, `push *remotepush.Coordinator`, `start *startfast.Service`) in place of embedded per-subsystem mutexes and maps.

**Why this core cannot be split further.** The remaining `22` files implement one coupled liveness and barrier cycle across four concurrent goroutine roles:
1. **Pass admission (`pass.go`, `live_scale.go`, `command.go`)** checks `gateRestart` (`restartGateMu` / `restartPendingWait`), claims lanes against `active` / `activeItems` (`mu`), and launches detached workers.
2. **Completion and background examination (`examine_coordinator.go`, `loop.go`)** receives worker wakeups on `completions`, tracks `examiningRuns` and `examinations` (`sync.WaitGroup`), and acquires a `restartMechanical` read hold (`restartSettlements`) while settling a candidate so an in-place binary replacement cannot cut off a half-recorded gate verdict or landing.
3. **Post-landing roll and in-place `exec` replacement (`post_landing.go`, `restart.go`, `restart_work.go`, `restart_examination.go`)** must block new admissions (`restartGateMu`), wait for `restartSettlements` and `examinations` to drain without killing detached worker processes, and `exec` the new `tillr-drain` binary in place.
4. **Startup re-adoption and operator stop (`recovery.go`, `end_unfinished_runs.go`, `unlaunched_claim.go`, `trigger.go`)** re-adopts live worker leases written before `exec`, retracts unlaunched claims, and cancels `loopCtx` (`sessionStop` under `sessionMu` / `pollReaderMu`) when `drain_sessions` records an operator stop.

Splitting pass admission, examination settlement, and the `exec` restart barrier into separate Go packages would either require mutual callback interfaces cycling on every state transition or split lock acquisition order across `mu`, `restartMechanical`, and `restartGateMu`. Keeping them together gives `drain` one job: *coordinate live passes, background examinations, and in-place restarts over single-job subsystem packages*.

### 3.1 Coexisting with live queue edits to `drain` and `just pack-sync` (`D-DPD5`)

**Designer's decision (`D-DPD5`); the owner may overturn it.** The extractions land while the live drain continues landing ordinary bug fixes and features to `drain` and keeping `yolo-packs/tillr/` synchronized. Four rules prevent conflict storms:

1. **Whole-file `git mv` plus per-package `drain/<pkg>_bridge.go` forwarding.** Each extraction moves whole `.go` and `*_test.go` files (`git mv tools/tillr-drain/drain/<f>.go tools/tillr-drain/internal/<pkg>/<f>.go`) and places type aliases (`type X = <pkg>.X`) and 1–5 line `(l *Loop)` forwarding wrappers in a dedicated `tools/tillr-drain/drain/<pkg>_bridge.go` file.

An in-flight lane editing one of the `4`–`19` moved `.go` files in that single commit is resolved by Git's rename-aware three-way merge (`git merge-tree`) or one bounded conflict-fix pass because each extraction touches `8`–`30` source+test files (`git diff --find-renames` stays within or near [`.tillr.toml`](../../.tillr.toml)'s advisory `file_limit = 27`, `added_line_limit = 1200`).
2. **Disjoint `drain/loop.go` and `drain/pass.go` edits.** Concurrent extractions in the same wave **never both edit `drain/loop.go` or `drain/pass.go`**: in multi-item waves, moved `(l *Loop)` methods forward from `drain/<pkg>_bridge.go` using existing `l.cfg` fields, `struct Loop` field removals happen only in solo spine waves (`E01`, `E05`, `E17`, `E18`, `E20`, `E22`), and when a Go type alias (`type x = <pkg>.X`) requires exporting a cross-package method or struct field on `<pkg>.X` (because Go forbids defining methods on a type alias in `drain` or referring to unexported fields/methods across packages), concurrent items in the wave update strictly disjoint caller file sets in `drain/*.go` and `drain/*_test.go` (`E02` in `ab7bf375`; `E03` in `D-DPD10`, disjoint from `E04` in `D-DPD11`; `E06` in `D-DPD13` and `E07` in `D-DPD14` on 100% disjoint caller files in Wave 4).
3. **Disjoint shared gate tables (`go-test-edges.json` and `classification_scan_test.go`).** Within every multi-item wave ([§3.3](#33-the-22-extraction-queue-items-e01e22)), **at most one item** moves tests listed in [`tools/gate/go-test-edges.json`](../../tools/gate/go-test-edges.json) (`EdgeB > 0`), and **at most one item** moves files listed in [`tools/gate/classification_scan_test.go`](../../tools/gate/classification_scan_test.go), [`tools/tillr-gate/classification_scan_test.go`](../../tools/tillr-gate/classification_scan_test.go), and [`tools/tillr-drain/drain/classification_scan_test.go`](../../tools/tillr-drain/drain/classification_scan_test.go) (`CScan > 0`). ## 4. Stopping Decay: Structural Rule and Automated Pre-Merge Ratchet

**Designer's decision (`D-DPD8`); the owner may overturn it.** Splitting a package once decays unless an automated pre-merge check refuses changes that put reverse imports, lateral cycles, or new domain files back onto `drain.Loop`. Consistent with [`D-GR47`](../reference/gate.md#D-GR47), `E01` adds `tools/tillr-drain/architecture_test.go` (in the root `github.com/mschulkind-oss/tillr-drain` package, which is **not** in `DeferredProofPackages` and runs `TestArchitecture` in `< 0.2 s` before every merge on any `tools/tillr-drain/...` change via `"read_tests"` in [`tools/gate/go-test-edges.json`](../../tools/gate/go-test-edges.json)) and extends `TestDrainSubpackageIsolation` in [`tools/tillr-gate/goaffected/selection_test.go`](../../tools/tillr-gate/goaffected/selection_test.go) to enforce four invariants:

1. **Universal [`D-GR47`](../reference/gate.md#D-GR47) leaf and `internal/*` isolation.** Dynamic `go list -json ./...` inspection over `tools/tillr-drain` refuses **any** package under `tools/tillr-drain/...` other than root `github.com/mschulkind-oss/tillr-drain` and `github.com/mschulkind-oss/tillr-drain/drain` that imports `drain` or root `tillr-drain` in `Imports`, `TestImports`, or `XTestImports`. New subpackages are covered automatically on creation without editing a central list.
2. **Self-declared layer DAG (`// tillr-arch: layer=<N> imports=<csv>`).** Every extracted `tools/tillr-drain/internal/<pkg>/doc.go` (excluding the pre-existing `internal/testinputs` fixture helper) carries a one-line header naming its integer layer (`0`–`5`, or same-layer sub-rank where `runhistory` imports `storelog`) and its allowed `internal/*` imports. `architecture_test.go` parses every extracted `internal/*/doc.go`, verifies the declared graph is acyclic and strictly downward, and fails if `go list` finds any undeclared `internal/*` import in code or tests. Because each package declares its header in its own `doc.go`, concurrent extraction waves never edit a shared architecture table.
3. **Monotonic ratchet on `tools/tillr-drain/drain` itself.** Without a ceiling on `drain`, new features can still land as extra `.go` files or extra mutexes on `struct Loop`. `architecture_test.go` enforces:
   - *Filename allowlist:* In `E01`, `drain/` is frozen to the non-test `.go` filenames remaining on `drain/` after `E01`'s move (`242` files at `be08e50b` after moving `17` of `259`, seeded from `E01`'s `base_sha`) plus `*_aliases.go` / `*_bridge.go` files (where `*_aliases.go` and `*_bridge.go` files are AST-checked to contain only `type` aliases, `const`/`var` re-exports, `init`, and `<= 10`-line forwarding functions), so no extraction `E02`–`E21` conflicts on `architecture_test.go` while **zero new domain `.go` files can be added to `drain/`**. In `E22`, the allowlist shrinks permanently to the remaining core coordinator files (`+ *_aliases.go` / `*_bridge.go`).
   - *`struct Loop` field and lock ceiling:* `go/ast` inspection of `type Loop struct` in `drain/loop.go` caps field count (`<= 159` seeded in `E01` at `59c72862`, `150` at `be08e50b`, ratcheted down to `<= 45` in `E22`) and `sync.Mutex`/`sync.RWMutex` count (`<= 26` seeded in `E01` at `59c72862`, `25` at `be08e50b`, ratcheted down to `<= 8` in `E22`).
4. **Module-wide AST invariant scans.** `definition_test.go` (`E04`/`E09`), `trunk_transaction_test.go` (`E17`), and `whole_log_test.go` (`E04`/`E05`/`E22`) cover `tools/tillr-drain/internal/*` (and `..` across `tools/tillr-drain/` for whole-module field/query scans), matching `classification_scan_test.go` (`pkgDir` including `"internal"`), so extracting files into `internal/*` never creates a blind spot for raw `item.State*` literals, unclassified `ActionHold` / `drainmodel.ActionHold` reasons, unlocked `landings` writes, or unindexed whole-table `events` scans.
