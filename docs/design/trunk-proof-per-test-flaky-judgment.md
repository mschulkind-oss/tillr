# The trunk proof judges flaky tests one test at a time and runs only the failing tests again

**Status:** Ruled in part on 2026-11-28 ([`OQ-TPF2`](#OQ-TPF2) option A: leaf subtest granularity; [`OQ-TPF3`](#OQ-TPF3): disable a detected flake and file its fix so it does not block the current proof, accept the repair when the named test passes once, leave extra checking to the fixer, and re-run the same loop if it fails in a flaky way again), and open for the owner's decisions in [`OQ-TPF1`](#OQ-TPF1) and [`OQ-TPF4`](#OQ-TPF4). **Nothing in this design is built yet** (`rg -n 'prove-disabled' tools/tillr-drain` returns nothing, and `disabledPath` in [`tools/tillr-gate/enable.go`](../../tools/tillr-gate/enable.go) keys markers only on whole declaration IDs); **Slices 1 and 2** depend only on [`OQ-TPF2`](#OQ-TPF2) and [`OQ-TPF3`](#OQ-TPF3) and can start now ([Section 8](#8-build-slices)). Aside from the dated owner rulings quoted verbatim in [Section 1.1](#11-owner-direction-2026-11-28-rulings-and-provenance) and [the Decision Ledger](#decision-ledger), every proposed mechanism, option, slice breakdown, and leaning below (`D-TPF1` through `D-TPF5`) is recorded from an operator request as **the designer's analysis and decision, not an owner ruling** ([decision provenance review](../tillr/decision-provenance-review.md#6-how-this-stops-happening), [`OQ-PR21` and `OQ-PR22`](../tillr/decision-provenance-review.md#decision-ledger)); the owner may overturn any of those five designer's decisions. No Go code or configuration is changed in this commit.

> **In short.** On 2026-11-27, `go-test-tillr-drain` ran twice on commit `50e065bc`: run one failed only `TestWhyAfterRestartOverLiveEvaluator/resumed_segment`, and run two failed only `TestAnOperatorStopInterruptsTheBackoff` and `TestIdleLoopRunDoesNotReplanUntilChange` (`16 / 249` = `6.43%` failure rate across `.rolling/logs`, even after an earlier fix in `929285ab` landed). Each of the three tests passed once and failed once on the same tree, yet whole-check contradiction disabling ([Landing Principle §17](./landing-principles.md#17-disable-a-flaky-check-file-its-repair-and-count-it-neither-green-nor-blocking), [`D-GR21`](../reference/gate.md#D-GR21)) saw only `(fail, fail)` on `go-test-tillr-drain`, disabled nothing, held `refs/tillr/green` back all day, and left an operator filing per-test items by hand. On 2026-11-28, the owner settled two rules: per-test disabling operates at leaf subtest granularity (`go-test:<module>:<pkg>:<Parent>/<Sub>`, [`OQ-TPF2`](#OQ-TPF2)), and a detected flake is disabled and sent for a fix without blocking the proof in progress, its repair lands when the named test passes once (`--prove-disabled`), how the fixer convinces itself is left to the fixer, and a test that flakes again re-enters the same loop ([`OQ-TPF3`](#OQ-TPF3)). [`OQ-TPF1`](#OQ-TPF1) puts the general flake-detection rule across the trunk proof, culprit bisection, repair checks, and lane gates to the owner, and [`OQ-TPF4`](#OQ-TPF4) covers cross-commit input keys before Landlock.

**Why it matters.** A 2,144-test suite with three `2%–6%` load-sensitive flakes fails as a whole on most runs even when zero trunk commits broke anything, starving `refs/tillr/green` (`D-GR5`), fooling culprit bisection into filing false `fixer-main-<tip>` items or reverting innocent commits, and forcing manual triage.

**The shape.** [Section 1](#1-owner-direction-the-2026-11-27-incident-and-the-2026-11-28-review) records the 2026-11-27 incident, the three code gaps behind it, and the owner's 2026-11-28 review; [Section 2](#2-the-unit-of-contradiction-exclusion-and-automatic-repair-filing) specifies leaf subtest selectors ([`OQ-TPF2`](#OQ-TPF2)), active exclusion in `tillr-gate shards`, and `flaky-*` filing; [Section 3](#3-how-flake-detection-works-today-and-the-general-rule-across-proof-bisection-and-repairs) states how flake detection works and fails today across every test failure site and compares the three general detection rules in [`OQ-TPF1`](#OQ-TPF1); [Section 4](#4-the-repair-item-and-its-single-pass-verify-step) folds in [`OQ-TPF3`](#OQ-TPF3)'s single-pass `flaky-*` gate while keeping the measured failure-rate and contention numbers as background for fixers; [Section 5](#5-what-carries-over-when-the-trunk-moves) defines moving-tip carryover alongside [`gate-test-caching.md`](./gate-test-caching.md) and [`trunk-repair-on-moving-trunk.md`](./trunk-repair-on-moving-trunk.md); [Section 6](#6-check-against-landing-principles) audits all seventeen landing principles; [Section 7](#7-what-is-deliberately-not-done) lists non-goals; [Section 8](#8-build-slices) names which build slices can start now and which wait on [`OQ-TPF1`](#OQ-TPF1) or [`OQ-TPF4`](#OQ-TPF4); and [Section 9](#9-open-questions) puts [`OQ-TPF1`](#OQ-TPF1) and [`OQ-TPF4`](#OQ-TPF4) to the owner.

**Cost.** When a heavy Go suite is green, runtime cost is zero extra subprocesses (`go test -json` is already parsed in [`tools/tillr-gate/shards`](../../tools/tillr-gate/shards)). Under [`OQ-TPF3`](#OQ-TPF3), verifying a `flaky-*` repair runs only the named test once (`~1–30 s` instead of `6.6–38.9 min` for a 6-shard suite). When `1–3` tests fail without a prior pass on those inputs, extra diagnostic cost is `0 s` under [`OQ-TPF1`](#OQ-TPF1) Option A and `~1–40 s` under Options B and C.

### 1.3 Three code gaps that produced the stall and the escaped fix

1. **Contradiction memory is keyed on whole check declarations, not test selectors.** `treeFingerprint` in [`tools/tillr-gate/memory.go`](../../tools/tillr-gate/memory.go) and `disabledPath(checkID)` in [`tools/tillr-gate/enable.go`](../../tools/tillr-gate/enable.go) record `pass` and `fail` only for `"go-test-tillr-drain"` as a single unit. Whenever two or more flaky tests alternate across runs of a 2,144-test suite, the declaration records `(fail, fail)` and never triggers rule 3 of `Classify` in [`tools/tillr/checkresult/classify.go`](../../tools/tillr/checkresult/classify.go).
2. **Live check execution does not yet exclude disabled units or pass `--prove-disabled`.** As noted under *Not enforced* in [Landing Principle §17](./landing-principles.md#17-disable-a-flaky-check-file-its-repair-and-count-it-neither-green-nor-blocking), live `tillr-gate checks --heavy-tree` only annotates `outcome.Memory = "flaky"` in `annotateMemory` ([`tools/tillr-gate/memory.go`](../../tools/tillr-gate/memory.go)), `tillr-gate shards` has no flag or store lookup to skip disabled tests, and `tillr-drain` never passes `--prove-disabled` (`rg -n 'prove-disabled' tools/tillr-drain` returns nothing).
3. **`flaky-*` repair items bypass named-check verification before merge.** In [`tools/tillr-drain/drain/loop.go`](../../tools/tillr-drain/drain/loop.go) and [`tools/tillr-drain/drain/fixer_gate.go`](../../tools/tillr-drain/drain/fixer_gate.go), `settleFixerGate` runs only for `IsTrunkFixer` (`fixer-main-<sha>`), not for `IsFlakyRepairItem` (`flaky-<slug>`). ## 2. The unit of contradiction, exclusion, and automatic repair filing

<a id="21-the-per-test-check-selector-d-tpf1-subject-to-oq-tpf2"></a>

### 2.1 The per-test check selector and leaf subtest granularity ([`OQ-TPF2`](#OQ-TPF2), [`D-TPF1`](#D-TPF1))

`tillr-drain` already defines a self-contained Go test selector grammar in `GoSuiteFailures` and `JudgeHeavyGo` ([`tools/tillr-drain/internal/gatespans/heavy_go.go`](../../tools/tillr-drain/internal/gatespans/heavy_go.go)):

```text
go-test:<module>:<package-import-path>:<TestName>
```

Examples from commit `50e065bc`:

```text
go-test:tools/tillr-drain:github.com/mschulkind-oss/tillr-drain/drain:TestIdleLoopRunDoesNotReplanUntilChange
go-test:tools/tillr-drain:github.com/mschulkind-oss/tillr-drain/drain:TestAnOperatorStopInterruptsTheBackoff
go-test:tools/tillr-drain:github.com/mschulkind-oss/tillr-drain/drain:TestWhyAfterRestartOverLiveEvaluator/resumed_segment
```

`tillr-gate shards` (`RunCachedGroup` in [`tools/tillr-gate/shards/cached.go`](../../tools/tillr-gate/shards/cached.go) and uncached shard execution in [`tools/tillr-gate/shards/runner.go`](../../tools/tillr-gate/shards/runner.go)) already executes `go test -json` and parses every `TestEvent` (`Package`, `Test`, `Action`, `Output`). Under the owner's 2026-11-28 [`OQ-TPF2`](#OQ-TPF2) ruling (**option A**: leaf subtest granularity when a subtest fails, widening to the parent test only when the parent fails outside subtests; rejecting top-level-only Option B so sibling subtests stay active), `tillr-gate` attributes `go test -json` events as follows ([`D-TPF1`](#D-TPF1)):

1. **Pass attribution:** Every test or subtest that emits `"Action": "pass"` records a `pass` observation for its own selector (`.../TestWhyAfterRestartOverLiveEvaluator/first_segment`).
2. **Leaf-only fail attribution:** In `go test -json`, when `TestWhyAfterRestartOverLiveEvaluator/resumed_segment` fails while sibling `TestWhyAfterRestartOverLiveEvaluator/first_segment` passes, Go emits `"Action": "fail"` for **both** `TestWhyAfterRestartOverLiveEvaluator/resumed_segment` and the enclosing `TestWhyAfterRestartOverLiveEvaluator`. Recording a failure on the parent whenever a child failed would leave a false failure or contradiction on the parent after `resumed_segment` was disabled. Therefore, a test selector `T` that emits `"Action": "fail"` records a `fail` observation **if and only if no descendant subtest `T/<child>` also emitted `"Action": "fail"` in that run**.
3. **Widening to `<Parent>` only on outside-subtest failures:** A failure inside `t.Run("resumed segment", ...)` is recorded solely against `.../TestWhyAfterRestartOverLiveEvaluator/resumed_segment` (keeping `first_segment` active in the proof), whereas a `t.Fatal` in `TestWhyAfterRestartOverLiveEvaluator` outside `t.Run` (or after all subtests pass) has zero failing descendants and is recorded against `.../TestWhyAfterRestartOverLiveEvaluator`.

### 2.2 Per-test contradiction markers and per-test log slicing

When `tillr-gate` evaluates a Go suite (`tillr-gate shards` invoked by `go-test-*`, or `tillr-gate go-affected`) with `--store <results-dir>`:

1. **Per-test output slicing:** From each shard's `TestEvent` stream, the runner buffers lines by `ev.Test` (preserving parent preamble lines emitted before `t.Run` when slicing a subtest). When a test fails or contradicts a stored record, `copyDisabledLog` ([`tools/tillr-gate/enable.go`](../../tools/tillr-gate/enable.go)) writes **only that test's output slice** (`<episodeKey>.fail.log` and `<episodeKey>.pass.log`, typically `20–200` lines) rather than copying a multi-megabyte 6-shard suite log.
2. **Classification through the single classifier ([`D-GR23`](../reference/gate.md#D-GR23)):** Each observed test selector is classified via `checkresult.Classify` ([`tools/tillr/checkresult/classify.go`](../../tools/tillr/checkresult/classify.go)) against `<store>` using its `CheckID = "go-test:<module>:<pkg>:<TestName>"` and its test input fingerprint ([Section 5.2](#52-three-state-classes-across-a-moving-tip-t1---t2)).
3. **Contradiction -> atomic `DisabledMarker`:** When the store holds both a `pass` and a `fail` for the same `(CheckID, Fingerprint)` (and that episode is not in `resolved_episodes`), `writeRule3Marker` atomically publishes `<store>/disabled/<sha256(CheckID)>.json`. Because `disabledPath` hashes `CheckID` rather than `Fingerprint` ([`D-GR22`](../reference/gate.md#D-GR22)), later commits that edit `tools/tillr-drain/` **never** silently re-arm an unrepaired flaky test.

### 2.3 Excluding disabled tests in `tillr-gate shards` so the rest of the suite proves the trunk green

Before `tillr-gate shards` partitions a package's discovered `Test*` functions across shards (`Assign` in [`tools/tillr-gate/shards/runner.go`](../../tools/tillr-gate/shards/runner.go)):

1. **Read active disabled selectors for the package:** Scan `<store>/disabled/*.json` for markers whose `CheckID` has prefix `go-test:<module>:<pkg>:` (excluding any selector passed via `--prove-disabled`).
2. **Exclude top-level disabled tests before `Assign`:** Any disabled top-level `TestName` (no `/`) is removed from `names` before `Assign` builds shard `-run` patterns. The test never starts, consumes zero CPU, and emits one synthetic `disabled` check classification carrying the marker's `Episode` and `RepairItem`.
3. **Exclude disabled subtests via verified Go `-skip` patterns ([`OQ-TPF2`](#OQ-TPF2)):** When `TestParent/sub1` is disabled and `TestParent` is assigned to a shard so `TestParent/sub2` still runs, `shards` passes `-skip <pattern>` to `go test`. Source inspection and execution against Go 1.27.3's `$GOROOT/src/testing/match.go` (`splitRegexp`, `alternationMatch.matches`, and `fullName`) establish two exact construction rules that `shards` must enforce:
   - **Never wrap slash-separated subtest patterns in parentheses:** In `splitRegexp`, `/` splits subtest levels only when parenthesis depth `cp == 0` (`(^TestA$/^sub1$)|(^TestB$)` fails to split on `/` and skips `TestA` as a whole or misses `sub1`). Multiple skip selectors in one shard are joined by **unparenthesized** top-level `|`, with each `/` segment anchored (`^TestA$/^sub1$|^TestB$`).
   - **Prune child subtest patterns under already-disabled parents (or sort shorter segment lists first):** In `alternationMatch.matches`, Go returns the first matching alternation branch even if `partial == true`, and `fullName` skips only when `skip && !partialSkip`. Ordering `^TestA$` ahead of (or dropping) `^TestA$/^sub1$` guarantees `TestA` is skipped completely whenever the parent itself is disabled.
   - Any `TestEvent` with `"Action": "skip"` matching an active disabled subtest selector is classified as `Outcome: Disabled` (never `Pass` and never `Skipped`).
4. **Suite verdict aggregation — both before and upon detection in the current proof ([`OQ-TPF3`](#OQ-TPF3)) — and `memory.go` safety:**
   - Whether a test was already disabled before `go-test-*` started or becomes newly `disabled` upon flake detection during the current proof ([Section 3.2](#32-one-general-detection-framework-and-how-the-three-candidate-rules-differ-oq-tpf1-d-tpf3)), a suite with `N_pass >= 0` passed tests, `N_disabled >= 1` disabled tests, and **zero** non-disabled failed tests, build errors, crashes, or stalls aggregates to `pass` while listing `disabled` tests apart in the verdict and summary ([`D-GR21`](../reference/gate.md#D-GR21), [`OQ-TPF3`](#OQ-TPF3): *"if we detect a flake, it goes for a fix and is disabled so it doesn't block hte current proof"*). `refs/tillr/green` advances.
   - To prevent a suite-level remembered pass in [`tools/tillr-gate/memory.go`](../../tools/tillr-gate/memory.go) from outliving a `flaky-*` repair, `treeFingerprint` for `go-test-*` includes the sorted list of active disabled `go-test:<module>:...` selectors (or `tillr-gate enable` invalidates cached suite passes covering that module). Once `tillr-gate enable` clears the marker, the re-enabled test is immediately required on the next proof.

### 2.4 Automatic `flaky-*` repair filing and repeat-episode numbering by the loop

No new filing table or document directive is needed: `Loop.sweepDisabledMarkers` and `reconcileDisabledMarker` in [`tools/tillr-drain/drain/flaky_repair.go`](../../tools/tillr-drain/drain/flaky_repair.go) already scan `<store>/disabled/*.json` at pass start and after gate, replay, and heavy-proof steps, deduplicate against open `flaky-<slug>` items, file `flaky-go-test-tools-tillr-drain-...` on `TrunkFixerSeat` **with no document item block in any tracked Markdown file** ([`D-GR23`](../reference/gate.md#D-GR23)), stamp `marker.RepairItem`, and call `tillr-gate enable` once that item reaches `StateLanded`. When an already-repaired test is later detected flaky again on a new episode ([`OQ-TPF3`](#OQ-TPF3)), `reconcileDisabledMarker` sees `flaky-<slug>` in `StateLanded` and allocates `flaky-<slug>-2` (`-3`, ...) automatically. Passing `go-test:<module>:<pkg>:<TestName>` as `marker.CheckID` needs only one guard ([`D-TPF2`](#D-TPF2)): cap slug length with a trailing 12-hex SHA-256 suffix when `len(slug) > 96` so deeply nested subtest names never exceed filesystem path limits under `<lane-root>/<item-id>/worktree`.

## 3. How flake detection works today, and the general rule across proof, bisection, and repairs

### 3.1 How a flaky test is detected today — and what is missed

Asking `"how exactly do we detect flakes in the trunk proof?"` on `HEAD` exposes a split between the classifier library and the four live call sites that actually run Go tests:

1. **Classifier library vs. live trunk proof (`checkresult.Classify` in [`tools/tillr/checkresult/classify.go`](../../tools/tillr/checkresult/classify.go) vs. [`tools/tillr-gate/memory.go`](../../tools/tillr-gate/memory.go) and [`tools/tillr-gate/shards/`](../../tools/tillr-gate/shards/)):**
   - **What exists:** Rule 3 of `checkresult.Classify` defines a flake as a same-fingerprint `(pass, fail)` contradiction in `.git/tillr-gate/results/`, and `tillr-gate classify --store` (`writeRule3Marker` in [`tools/tillr-gate/enable.go`](../../tools/tillr-gate/enable.go)) writes `disabled/<sha256(checkID)>.json`.
   - **What actually runs in the proof — and what is missed:** `JudgeHeavy` ([`tools/tillr-drain/internal/gatespans/heavy_steps.go`](../../tools/tillr-drain/internal/gatespans/heavy_steps.go)) invokes `tillr-gate checks --heavy-tree`, which runs `treeMemory.run` and `annotateMemory` in [`tools/tillr-gate/memory.go`](../../tools/tillr-gate/memory.go). `memory.go` keys `.git/tillr-gate/results/` only on **whole check declarations** (`go-test-tillr-drain`), `tillr-gate shards` never reads or writes `resultStore`, and `annotateMemory` calls `classifyCheck` without `Marker`, `StoredPass`, or `StoredFail` — it only sets `outcome.Memory = "flaky"` when a whole check passes after a prior pass and fail, and **never writes a `DisabledMarker` or skips anything**. As a result, live trunk proofs **never automatically disable a flaky test today**: alternating flakes in a 2,144-test suite record `(fail, fail)` on `go-test-tillr-drain` (`50e065bc`), and any failure whose inputs changed since `refs/tillr/green` has no stored `pass` to contradict against.
2. **Focused reruns ahead of a later trunk proof (`runFocusedFailingTests` in [`tools/tillr-drain/internal/gatespans/heavy_steps.go`](../../tools/tillr-drain/internal/gatespans/heavy_steps.go) and `JudgeHeavyGo` in [`heavy_go.go`](../../tools/tillr-drain/internal/gatespans/heavy_go.go)):**
   - **What runs today:** When a proof fails on Go tests, `SaveHeavyFailingTests` records those test names. At the start of the next proof on the same module, `runFocusedFailingTests` runs only those saved tests via `JudgeHeavyGo` (`go test -json -count=1 -run ...`) without consulting or updating `.git/tillr-gate/results/`.
   - **What is missed:** For a `6%` flake that failed in proof 1, `runFocusedFailingTests` passes `~94%` of the time on the identical commit, logs `"focused rerun passed; running whole suite"`, and treats the test as cured rather than recognizing that `fail` followed by `pass` on the same tree proved a flake.
3. **Culprit bisection and automatic revert (`FindFirstRed` in [`tools/tillr-drain/heavyrun/heavy_attribution.go`](../../tools/tillr-drain/heavyrun/heavy_attribution.go) and `SearchFirstRed` / `attribute` / `offerRevert` in [`tools/tillr-drain/heavyrun/heavy.go`](../../tools/tillr-drain/heavyrun/heavy.go)):**
   - **What runs today:** When a test fails in the proof, `SearchFirstRed` replays that single test via `JudgeHeavyGo` at `base` (`refs/tillr/green`) and at `commits[len(commits)-1]` (the last commit in `base..tip` touching the check's declared reads — often `tip` itself, or an ancestor whose test inputs match `tip`), then bisects `commits` with `bisectHeavyRed` and checks `candidate^1`. None of those replays reads or writes `.git/tillr-gate/results/`.
   - **What is missed:** For a `6%` flake that failed on `tip`, `replay(commits[last])` passes `~94%` of the time. `SearchFirstRed` returns `fault = true` with `"the last candidate commit touching the check's reads is green"`, **keeps `run.Result` red**, leaves `refs/tillr/green` unmoved, and files a deterministic trunk-break item (`fixer-main-<tip>`) instead of detecting a flake. Worse, in the remaining `~6%` where `commits[last]` also fails, if the flake fails on an innocent midpoint commit `M` and passes on `M^1`, `SearchFirstRed` blames `M` and `offerRevert` automatically reverts an innocent landing.
4. **Repair checks and pre-merge lane gates (`settleFixerGate` in [`tools/tillr-drain/drain/fixer_gate.go`](../../tools/tillr-drain/drain/fixer_gate.go) and `acquitTrunkAlreadyRed` / `settleTrunkAlreadyRed` in [`tools/tillr-drain/drain/trunk.go`](../../tools/tillr-drain/drain/trunk.go)):**
   - **What runs today — and what is missed:** Deferred-package `flaky-*` items (`929285ab`) bypassed `settleFixerGate` completely (fixed by [Section 4.1](#41-settled-pre-merge-verification-and-re-entry-loop-for-flaky--items-oq-tpf3-d-tpf4)). Meanwhile, when an un-disabled trunk flake fails inside an ordinary lane's `go-affected` gate, `settleTrunkAlreadyRed` replays `base` once without per-test contradiction memory: `base` passes `~94%` of the time, so the innocent lane candidate is convicted and returned to its worker. And when an incomplete `flaky-*` repair lands and flakes again on `main`, it hits gaps 1–3 above instead of cleanly re-entering `flaky-<slug>-2`.

### 3.2 One general detection framework, and how the three candidate rules differ ([`OQ-TPF1`](#OQ-TPF1), [`D-TPF3`](#D-TPF3))

The owner's 2026-11-28 objection identifies why [`OQ-TPF1`](#OQ-TPF1) cannot just ask *where* to place one proof rerun: tillr needs **one general rule** for separating a broken test from a flaky test across every site where a test fails, and [`OQ-TPF3`](#OQ-TPF3) invokes that rule at two exact transitions (`"if we detect a flake"` and `"if it fails again in a flakey way"`).

Three foundation pieces apply identically under every option in [`OQ-TPF1`](#OQ-TPF1) ([`D-TPF3`](#D-TPF3)):

1. **One shared per-test observation store across all committed-tree runs:** Every test execution on a committed trunk revision — proof shards, `runFocusedFailingTests`, `SearchFirstRed` bisection replays, revert checks, and lane-gate `base`/`tip` replays — feeds per-test `pass` and `fail` observations (`go-test:<module>:<pkg>:<TestName>`, leaf subtest granularity per [`OQ-TPF2`](#OQ-TPF2)) through `checkresult.Classify` against `.git/tillr-gate/results/` keyed by that test's input fingerprint ([Section 5.2](#52-three-state-classes-across-a-moving-tip-t1---t2)). Unmerged candidate branches (`head_sha` in a lane gate or `--prove-disabled` on a `flaky-*` branch) never write `DisabledMarker`s from their own candidate failures (`1` fail on a candidate branch returns to that worker).
2. **Disable on detection and re-aggregate the current proof ([`OQ-TPF3`](#OQ-TPF3)):** Whenever `Classify` sees both `pass` and `fail` for the same `(testSelector, inputFingerprint)` — whether on initial shard completion, on a diagnostic confirmation run, or mid-bisection when `SearchFirstRed` replays a commit whose test inputs match `tip` — tillr atomically writes `disabled/<sha256(testSelector)>.json` with both per-test logs, files `flaky-<slug>` (or `flaky-<slug>-2`, `-3`, ... after an earlier repair), aborts any in-progress bisection for that test, and **re-aggregates the current proof verdict with that test counted `disabled` (`neither pass nor fail`)** so a detected flake never blocks the proof in progress.
3. **Exclusions that are never classified as flaky ([`D-TPF3`](#D-TPF3)):** Timeouts and deadlocks (`panic: test timed out after ` or `fatal error: all goroutines are asleep - deadlock!`, [`D-GR31`](../reference/gate.md#D-GR31)), compilation errors, unnamed binary crashes, and watchdog stalls (`ExitStalled = 6`, [`D-GR16`](../reference/gate.md#D-GR16)) are never treated or probed as flaky tests; a stalled or process-errored diagnostic run classifies as `unknown` ([Landing Principle §8](./landing-principles.md#8-a-gate-that-cannot-answer-must-say-which)).

Where the three options in [`OQ-TPF1`](#OQ-TPF1) differ is **the detection rule itself when a non-timeout test fails with no stored `pass` yet on its current inputs**:

| Dimension | **Option A — Passive same-input contradiction across ordinary runs only (`0` extra runs)** | **Option B — Single same-tree reproducibility check on uncontradicted failures (`fail + fail` = broken, `fail + pass` = flaky)** | **Option C — Short concurrent diagnostic burst on uncontradicted failures (`K = 4` parallel `GOMAXPROCS=1` runs; any `pass` = flaky, `4 / 4` `fail` = broken)** |
| :--- | :--- | :--- | :--- |
| **General rule separating broken from flaky** | A test is flaky iff two **ordinary** runs that tillr already performs on identical test inputs disagree (`pass` and `fail`). A failure with no stored `pass` is treated as broken until an ordinary replay or later run passes on the same inputs. | A commit's test failure counts as broken (`fail`) only when reproduced once on the identical tree (`fail + fail`) with no stored `pass`. If the single confirmation run passes (`fail + pass`), the test contradicted itself and is `disabled` + `flaky-*`. | When a test fails with no stored `pass` on its current inputs, compile `./<pkg>` once (`go test -c`) and run only that test `K = 4` times concurrently under `GOMAXPROCS=1` (`~1x` single-test wall time). Any `pass` = `disabled` + `flaky-*`; `4 / 4` `fail` = broken. |
| **Trunk proof (`JudgeHeavy`)** | Flakes whose inputs already passed an earlier proof contradict immediately (`0` extra runs -> `disabled` + `flaky-*`, current proof stays green). First-seen failures on newly touched inputs enter `SearchFirstRed` directly. | Uncontradicted failures run once more on `tip` (`~1–30 s`). `94%` of `6%` flakes pass right on `tip`, become `disabled` + `flaky-*`, and let the current proof advance `refs/tillr/green` without checking out `base` or bisecting. (`50%` coin-flip flakes still fail twice `25%` of the time.) | Catches both low-rate flakes (`0.0001%` false-broken at $p = 6\%$) and `50%` coin-flip or contention-only flakes (`(0.5)^5 = 3.1%` false-broken) right on `tip` in `~1x` single-test wall time, disabling the flake and advancing `refs/tillr/green`. |
| **Culprit bisection & auto-revert (`SearchFirstRed` / `offerRevert`)** | When `SearchFirstRed` replays `commits[last]` (same test inputs as `tip`) and sees `pass`, that contradicts `fail@tip`, disables the test, files `flaky-*`, aborts bisection, and turns the current proof green instead of filing `fixer-main-<tip>`. *Residual risk:* if `commits[last]` differs in inputs or the flake fails twice (`p^2`) and flips on an innocent midpoint `M` vs. `M^1`, `M` can still be falsely blamed/reverted. | Only `fail + fail` tests enter bisection, any same-input `pass` during bisection aborts into `disabled` + `flaky-*`, and blaming/reverting a culprit `C` whose inputs differ from `tip` also requires `fail + fail` on `C` (bounding false culprit reverts to $p^4$, e.g. `0.0016%` at $p = 6\%$). | Virtually never enters bisection on a flake, and confirming a candidate culprit `C` whose inputs differ from `tip` before auto-revert drives false culprit reverts below $p^{10}$. |
| **A repair's check (`flaky-*` & `"fails again in a flakey way"`) and lane gates** | Pre-merge `flaky-*` gate runs `1` time ([`OQ-TPF3`](#OQ-TPF3): `1` pass lands; `1` fail returns to fixer). On `main`, a re-enabled incomplete fix re-disables (`flaky-<slug>-2`) once it either passes a proof and later fails or fails `tip` and passes its `SearchFirstRed` replay. In lane `go-affected`, a new flake whose `base` replay passes still bounces the lane worker once. | Pre-merge `flaky-*` gate still runs `1` time ([`OQ-TPF3`](#OQ-TPF3): `1` pass lands; `1` fail returns to fixer). Once on `main`, even if an incomplete fix fails on its **very first** post-enable proof, the `1` check on `tip` catches `fail + pass` (`94%` at $p = 6\%$) -> `flaky-<slug>-2` immediately instead of reverting the fix. In lane gates, `1` confirmation run on `base`/`head` acquits most trunk flakes without bouncing the worker. | Pre-merge `flaky-*` gate **still runs `1` time** ([`OQ-TPF3`](#OQ-TPF3): `1` pass lands, zero burst bar to land a fix). Only **after** a test fails without a stored `pass` on `main` (or in lane failure diagnosis) does the `4`-worker burst run — separating `"fails again in a flakey way"` (`flaky-<slug>-2`) from `"fix deterministically broke the test"` (`4 / 4` fail -> revert / `fixer-main`). |
| **Sitting with *"a red is read once, never re-run"* ([`D-GR22`](../reference/gate.md#D-GR22), [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run))** | **Zero textual amendment:** every check and test runs at most once per step (`"A failed check costs exactly one run of that check"` holds literally). | **Substantive rule kept (`fail + pass` -> `disabled`, never `pass`); narrow amendment** to [`D-GR22`](../reference/gate.md#D-GR22) and [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) authorizing `1` same-tree reproducibility run on uncontradicted failures. | **Substantive rule kept (`fail + pass` -> `disabled`, never `pass`); broader amendment** to [`D-GR22`](../reference/gate.md#D-GR22) and [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) authorizing a `K = 4` concurrent diagnostic burst on uncontradicted failures (introducing a fixed width parameter `K`). |

### 3.3 Check against Landing Principle 11, Landing Principle 17, and the no-retry ruling

1. **Agreement with [Landing Principle §17](./landing-principles.md#17-disable-a-flaky-check-file-its-repair-and-count-it-neither-green-nor-blocking) ([`D-GR21`](../reference/gate.md#D-GR21)) and [`OQ-TPF3`](#OQ-TPF3):**
   [`D-GR21`](../reference/gate.md#D-GR21) states verbatim: `"The correct move for a flaky test is disable it, file an item to fix it, and don't let it block anything. It is not considered green, but it also doesn't let you block other things."` Applying `Classify` and `DisabledMarker` to `go-test:<module>:<pkg>:<TestName>` across proof runs and bisection replays implements [`D-GR21`](../reference/gate.md#D-GR21) and [`OQ-TPF3`](#OQ-TPF3) at the exact noun (`"a flaky test"`) the owner stated, rather than letting alternating flakes in a 2,144-test bundle mask each other as `(fail, fail)` or letting `SearchFirstRed` turn a `fail + pass` flake into `fixer-main-<tip>`.
2. **Agreement with [Landing Principle §11](./landing-principles.md#11-a-failure-is-diagnosed-not-waited-out):**
   [Landing Principle §11](./landing-principles.md#11-a-failure-is-diagnosed-not-waited-out) states: *"Determinism is established by observation: the same failure repeats under unchanged inputs, or strikes items that share nothing but the machinery. The test for any proposed failure mechanism is one question: what will be different on the next run, and how will the system know? A mechanism whose answer is 'time passed' is refused."*
   - A retry-to-green hopes time passed so a red disappears uninvestigated.
   - Under all three options in [`OQ-TPF1`](#OQ-TPF1), **no outcome clears a failure or lets it go undiagnosed**: repeated failure diagnoses a deterministic trunk regression (`SearchFirstRed` -> culprit revert or `fixer-main-<sha>`), and `(fail, pass)` on identical inputs diagnoses non-determinism (disables `t_i` and files `flaky-<slug>` with both logs). What differs between the two outcomes is **which repair path owns the defect** — culprit revert / `fixer-main-<sha>` for a broken trunk commit versus `flaky-<slug>` for a non-deterministic test — never whether a defect exists.
3. **How Options A, B, and C sit with [`D-GR22`](../reference/gate.md#D-GR22) and [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run):**
   - [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) (`status: accepted`, `stage: CURRENT`) defines a retry as re-running a failed check to erase the red (`"A retry in the gate is an assertion that the first red meant nothing... A later pass never erases the red that came before it"`), and also states literally: `"A failed check costs exactly one run of that check."` Designer/operator decision [`D-GR22`](../reference/gate.md#D-GR22) (`2026-11-21`, in [The designer's decisions](../reference/gate.md#the-designers-decisions)) likewise lists `"a live re-run"` among rejected mechanisms.
   - **Option A** obeys both the substantive rule and the literal one-run sentence without amending either document, relying on the shared per-test store across ordinary runs and `SearchFirstRed`'s existing replays.
   - **Options B and C** preserve the substantive rule — a subsequent `pass` **never** erases the first `fail` and **never** turns the test green (`disabled` + `flaky-*`) — while requiring the owner's authorization in [`OQ-TPF1`](#OQ-TPF1) to amend [`D-GR22`](../reference/gate.md#D-GR22) and [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) so an uncontradicted test failure can run once more (Option B) or in a `K = 4` concurrent burst (Option C) solely to separate `fail` from `disabled`.

## 4. The repair item and its single-pass verify step

### 4.1 Settled pre-merge verification and re-entry loop for `flaky-*` items ([`OQ-TPF3`](#OQ-TPF3), [`D-TPF4`](#D-TPF4))

Every `flaky-<slug>` repair item carries the disabled selector `go-test:<module>:<pkg>:<TestName>` and both per-test logs (`pass_log_ref` and `fail_log_ref`) in its criterion ([`FlakyRepairCriterionText`](../../tools/tillr-drain/drain/flaky_repair.go)). Under the owner's 2026-11-28 [`OQ-TPF3`](#OQ-TPF3) ruling (`"after the fix, we run it again, if it passes, that's good neough. let the fixer decide what to do. if it fails again in a flakey way, hten we run it through the same loop again"`), `Loop` settles a `flaky-*` candidate after the ordinary fast gate via `settleFlakyRepairGate` (extending [`tools/tillr-drain/drain/fixer_gate.go`](../../tools/tillr-drain/drain/fixer_gate.go), [`D-TPF4`](#D-TPF4)):

1. **Ordinary fast gate over the candidate's diff (`base..head`):** Runs `go-build`, `go-vet`, `elapsed-time` ([`tools/gate/checks/elapsed-time.json`](../../tools/gate/checks/elapsed-time.json), refusing new wall-clock timing bounds per [`D-GR17`](../reference/gate.md#D-GR17)), `commit-identity`, and any non-deferred `go-affected` packages.
2. **Anti-evasion verification on the named test selector (`--prove-disabled`):**
   - Unlike `fixer-main-<sha>` (where `settleFixerGate` drops `goTestAbsent` when a feature and its test were intentionally removed), **a `flaky-*` candidate is refused if the named test reports `goTestAbsent` (`"test not present at this commit"`) or `goTestSkipped` (`"test or enclosing test skipped at this commit"`)**. Under [`D-GR21`](../reference/gate.md#D-GR21) (*"re-enable it correctly, the test that was flaky"*) and [`D-GR17`](../reference/gate.md#D-GR17) (*"do not add a timeout, a retry or a longer wait as the fix"*), deleting, renaming, or skipping the test requires an explicit `owner` obstacle, never a silent pass.
3. **One targeted run of the named test — never the whole suite, and no gate repeat or stress bar ([`OQ-TPF3`](#OQ-TPF3)):**
   - Execute **only** the named test selector (`-run ^TestName$` or `^Parent$/^Sub$`) **once** with `-count=1` and `--prove-disabled` in isolated `TMPDIR` and `GIT_CONFIG_GLOBAL` directories at `repair` process priority (`nice 0` / `cpu.weight=400`, [`OQ-GR7`](../reference/gate.md#OQ-GR7)).
   - **One pass accepts the repair:** If that single run passes, `settleFlakyRepairGate` accepts the candidate, lands it, and runs `tillr-gate enable` to archive the episode and re-enable the test on `main` (closing the `929285ab` gap where a deferred-package `flaky-*` item merged with zero runs of the named test). **No fixed repeat count, no rate-derived stress run, and no mandatory `-race` run are required by the gate**; how the fixer convinces itself in its lane before committing is solely the fixer's choice ([Section 4.2](#42-measured-failure-rates-and-reproduction-tools-as-background-for-the-fixer)). If that single run fails, the candidate returns to the fixer as a normal gate failure without touching `<store>/disabled/`.
4. **Re-entering the same loop if the test flakes again after landing ([`OQ-TPF3`](#OQ-TPF3)):**
   - Once `tillr-gate enable` archives the resolved episode under `resolved/<hash>/`, the test runs normally in future trunk proofs. If the fix was incomplete and the test is later detected flaky again under [`OQ-TPF1`](#OQ-TPF1), tillr writes a fresh `DisabledMarker` so it does not block that proof either, and `reconcileDisabledMarker` ([`tools/tillr-drain/drain/flaky_repair.go`](../../tools/tillr-drain/drain/flaky_repair.go)) files `flaky-<slug>-2` (`-3`, ...) to run it through the same disable, file, and fix loop again.

### 5.2 Three state classes across a moving tip (`T1 -> T2`)

When `main` advances from `T1` to `T2` during or immediately after a trunk proof, per-test records split into three distinct carryover rules ([`D-TPF5`](#D-TPF5), with input-key strictness before [`OQ-GC1`](./gate-test-caching.md#OQ-GC1) put to the owner in [`OQ-TPF4`](#OQ-TPF4)):

1. **Active `DisabledMarker`s (`disabled/<sha256(testSelector)>.json`) ALWAYS carry over (`T1 -> T2`).**
   Whether `T2` edited `docs/` or `tools/tillr-drain/drain/loop.go`, an already-contradicted test remains `disabled` and excluded from `tillr-gate shards` until its `flaky-*` repair item lands and runs `tillr-gate enable` ([`D-GR22`](../reference/gate.md#D-GR22)). A busy trunk never re-arms a known flake.
2. **Completed `pass` observations carry over whenever `T1..T2` did not change that test unit's inputs.**
   `go-test-tillr-drain.json` declares `22` repository-wide `reads` entries across `11` modules, so whole-check `memory.go` invalidates the entire suite on almost any code commit. At the package/shard/test level:
   - A landing on `docs/`, `.justfile`, `tools/tillr-watch/`, or an unrelated leaf package changes **zero** inputs of `github.com/mschulkind-oss/tillr-drain/drain`. Every `pass` observation recorded on `T1` (including shards completed before `T1`'s proof was cancelled when `T2` landed, matching [`gate-test-caching.md`](./gate-test-caching.md#43-option-3-finer-duration-balanced-shards-and-per-shard-result-checkpointing) Option 3) carries straight over to `T2` without re-running.
   - Even when `T2` edits a sibling module such as `tools/tillr-view/`, narrowing per-test edge inputs via `read_tests` ([`D-GR44`](../reference/gate.md#D-GR44)) and `build_tests` ([`D-GR51`](../reference/gate.md#D-GR51)) preserves the input key of every `drain` test that does not build or read `tillr-view`.
3. **Prior `fail` observations on `T1` either complete a cross-tip contradiction or run first (`fail-fast`) on `T2`:**
   - **Test inputs unchanged between `T1` and `T2` (`fp_T1(t) == fp_T2(t)`):** `t`'s `fail` record from `T1` stays bound to `fp_T1(t)`. If `T1`'s proof was cancelled before confirming `t`, `T2`'s proof runs `t` **first**: if `t` passes on `T2`, `Classify` immediately pairs `(fail@T1, pass@T2)` on identical `fp(t)`, marks `t` `disabled`, and files `flaky-<slug>`. If `t` fails again on `T2`, `(fail@T1, fail@T2)` confirms `t` is deterministically red without waiting `10–25 min` for `6` full shards.
   - **Test inputs changed between `T1` and `T2` (`fp_T1(t) != fp_T2(t)`):** Because `T2` changed `t`'s code or declared edges, a `pass` on `T2` is **not** a contradiction of `fail@T1` — `T2` may have genuinely fixed a regression introduced on `T1` (matching [`trunk-repair-on-moving-trunk.md`](./trunk-repair-on-moving-trunk.md#21-option-a--revert-on-currenttip-extract-failing-go-test-cases-for-focused-replay-and-never-defer-on-an-unverified-input-touch-designers-leaning) Option A, which supersedes a red check on a demonstrated pass). Even here, `T2`'s proof **runs `T1`'s failed selectors `{t}` first (`--prior-failed`)** ahead of full shards: if `t` still fails on `T2`, the proof catches it in seconds (and applies the confirmation rule of [`OQ-TPF1`](#OQ-TPF1) if Option B or Option C is chosen); if `t` passes on `T2`, the remaining shards verify the rest of `T2`.

## 7. What is deliberately not done

1. **No suite-wide retry and no retry-to-green budget.** Re-running all `6` shards of `go-test-tillr-drain` on failure wastes `6.6–38.9 min` and trips unrelated flakes; crediting a `fail -> pass` flip as `pass` would violate [`D-GR21`](../reference/gate.md#D-GR21) and [gate check rules](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run).
2. **No static quarantine list or blob-pinned skip file without a `DisabledMarker` and open `flaky-*` item.** [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md#a-check-set-aside-from-the-verdict-is-narrow-ticketed-and-counted) notes that no static case-quarantine file exists; adding a hand-edited skip list in git would require commits to disable a flake and could outlive its repair. Store-backed `DisabledMarker`s + automatic `flaky-*` items + `tillr-gate enable` require zero hand-commits and cannot outlive the landed repair.
3. **No solo rerun of timed-out or deadlocked tests ([`D-GR31`](../reference/gate.md#D-GR31)) or stalled processes ([`D-GR16`](../reference/gate.md#D-GR16)).** A test that hit Go's timeout panic or `all goroutines are asleep - deadlock!` has already proved a hang/deadlock defect and would risk hanging the proof runner if re-executed.
4. **No whole-suite (`go-test-tillr-drain`) execution and no repeat-count or load-stress bar inside a `flaky-*` item's verify gate ([`OQ-TPF3`](#OQ-TPF3)).** Running `2,144` unrelated tests to verify a fix to one named test wastes `10–25 min` and exposes the repair candidate to *other* tests, and [`OQ-TPF3`](#OQ-TPF3) rules out fixed repeat counts and load-sized stress runs as gate requirements: the ordinary fast gate covers compile/import-affected non-deferred packages while `settleFlakyRepairGate` runs **only the named test selector once** (`--prove-disabled`), leaving extra reproduction runs to the fixer and re-entering the disable, file, and fix loop if the test flakes again later.
5. **No silent closing or re-arming of a `flaky-*` item when unrelated commits edit its package.** Under [`D-GR22`](../reference/gate.md#D-GR22), an unrepaired flaky test stays disabled across input changes until its `flaky-*` item lands and proves the test (`--prove-disabled`), rather than re-entering the trunk proof unfixed every time `tools/tillr-drain/drain/` is touched.
6. **No document item blocks in tracked Markdown.** Generated `flaky-*` items live solely in the queue store (`flaky_repair.go`), keeping tracked Markdown untouched ([`D-GR23`](../reference/gate.md#D-GR23)).

## 9. Open questions

[`OQ-TPF2`](#OQ-TPF2) and [`OQ-TPF3`](#OQ-TPF3) were ruled by the owner on 2026-11-28 and are compacted into [the Decision Ledger](#decision-ledger). Two questions remain open for the owner:

1. 💬 **OQ-TPF1: What general rule should tillr use to tell a flaky test apart from a broken test across the trunk proof, culprit bisection, repair checks, and lane gates?**

   On 2026-11-28 you pushed back on the earlier version of this question — `"this seems liek a more generic issue for flakey tests and bisection and trunk proof, no? I'm not entierly sure any of these are teh ansewr."` — and asked `"how exactly do we detect flakes in the trunk proof?"`. Your [`OQ-TPF3`](#OQ-TPF3) ruling (`"if we detect a flake, it goes for a fix and is disabled so it doesn't block hte current proof... if it fails again in a flakey way, hten we run it through the same loop again"`) depends directly on this rule at those two transitions.

   **How a flaky test is detected today — and what is not detected:**
   - *Trunk proof (`tillr-gate checks --heavy-tree` in [`memory.go`](../../tools/tillr-gate/memory.go) and [`shards/`](../../tools/tillr-gate/shards/)):* Although `checkresult.Classify` ([`classify.go`](../../tools/tillr/checkresult/classify.go)) defines a flake as a same-fingerprint `(pass, fail)` contradiction in `.git/tillr-gate/results/`, live trunk proofs key `memory.go` only on **whole check declarations** (`go-test-tillr-drain`), `tillr-gate shards` never reads or writes `resultStore`, and `annotateMemory` only sets `outcome.Memory = "flaky"` without ever writing a `DisabledMarker` or skipping any test. Live trunk proofs **never automatically disable a flaky test today**: alternating flakes in a 2,144-test suite record `(fail, fail)` (`50e065bc`), and a flake on newly changed inputs has no stored `pass` yet.
   - *Focused reruns, culprit bisection, and lane/repair checks:* `runFocusedFailingTests` ([`heavy_steps.go`](../../tools/tillr-drain/internal/gatespans/heavy_steps.go)), `SearchFirstRed` ([`heavy.go`](../../tools/tillr-drain/heavyrun/heavy.go)), `settleFixerGate` ([`fixer_gate.go`](../../tools/tillr-drain/drain/fixer_gate.go)), and `settleTrunkAlreadyRed` ([`trunk.go`](../../tools/tillr-drain/drain/trunk.go)) all run `go test -count=1` **outside** the contradiction store. When a `6%` flake failed in proof 1 and passes `runFocusedFailingTests` ahead of proof 2 (`~94%` of the time), tillr logs `"focused rerun passed; running whole suite"` and treats it as cured instead of flaky. Worse, when `SearchFirstRed` replays `commits[last]` (often `tip` itself or an ancestor with identical test inputs) and the `6%` flake passes (`~94%`), `SearchFirstRed` returns `"the last candidate commit touching the check's reads is green"`, **keeps the proof red**, holds `refs/tillr/green` back, and files a deterministic `fixer-main-<tip>` trunk-break item instead of disabling a flake; in the remaining `~6%`, if the flake fails on an innocent midpoint `M` and passes on `M^1`, `offerRevert` auto-reverts `M`. In an ordinary lane's `go-affected` gate, a `base` replay that passes (`~94%`) convicts the innocent lane worker.

   **One general rule across all options:** Every test run on a committed trunk revision (proof shards, focused reruns, `SearchFirstRed` bisection replays, revert checks, and lane-gate `base`/`tip` replays) reads and writes per-test `pass` and `fail` records in `.git/tillr-gate/results/` (excluding timeouts/deadlocks under [`D-GR31`](../reference/gate.md#D-GR31) and stalls under [`D-GR16`](../reference/gate.md#D-GR16)). Whenever any two runs on identical test inputs disagree (`pass` and `fail`) — during the suite run, a confirmation run, or mid-bisection — tillr writes `DisabledMarker`, files `flaky-*` (`-2`, `-3`, ...), aborts bisection for that test, and re-aggregates the current proof with that test `disabled` so it never blocks the proof in progress ([`OQ-TPF3`](#OQ-TPF3)). Unmerged candidate branches never disable a test from their own failures. The three options below differ in **the detection rule itself when a non-timeout test fails with no stored `pass` yet on its current inputs**:

   - **A — Passive same-input contradiction across ordinary runs only (`0` extra diagnostic runs).** A test is flaky if and only if two ordinary runs tillr already performs on identical test inputs disagree (`pass` and `fail`); failing once with no stored `pass` adds zero extra runs.
     - *Proof:* Flakes that already passed an earlier proof on the same inputs become `disabled` + `flaky-*` immediately and leave the current proof green; first-seen failures on newly changed inputs start culprit bisection.
     - *Culprit bisection:* When `SearchFirstRed` replays `commits[last]` (same test inputs as `tip`) and sees `pass` (`~94%` for a `6%` flake), that contradicts `fail@tip`, disables the test, files `flaky-*`, aborts bisection, and turns the current proof green instead of filing `fixer-main-<tip>`. *Residual gap:* if `commits[last]` changed the test's inputs, or the flake fails twice (`p^2`) and flips on an innocent midpoint `M` vs. `M^1`, bisection can still blame and auto-revert `M`.
     - *Repair's check & lane gate:* Pre-merge `flaky-*` runs `1` time per [`OQ-TPF3`](#OQ-TPF3) (`1` pass lands; `1` fail returns to the fixer). If an incomplete fix flakes again on `main`, a post-enable proof `pass` + later `fail` (or `fail@tip` + `pass` on its `SearchFirstRed` replay) re-disables it as `flaky-<slug>-2`. In lane `go-affected`, a new flake whose `base` replay passes once still bounces the lane worker once.
     - *Sitting with "a red is read once, never re-run":* Keeps [`D-GR22`](../reference/gate.md#D-GR22) and [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) literally unamended (`"A failed check costs exactly one run of that check"`).
   - **B — Single same-tree reproducibility check on uncontradicted failures (`fail + fail` = broken, `fail + pass` = flaky).** Whenever a non-timeout test fails with no stored `pass` on its current inputs, run that single test **once more** (`-count=1`) on the identical tree before calling that commit broken (`fail`).
     - *Proof:* Uncontradicted failures run once more on `tip` (`~1–30 s`). `94%` of `6%` flakes pass right on `tip`, become `disabled` + `flaky-*`, and let the current proof advance `refs/tillr/green` without checking out `base` or starting bisection.
     - *Culprit bisection:* Only `fail + fail` tests enter `SearchFirstRed`, any same-input `pass` during bisection aborts into `disabled` + `flaky-*` and turns the proof green, and blaming/auto-reverting a candidate culprit `C` whose inputs differ from `tip` also requires `fail + fail` on `C` (bounding false culprit reverts to $p^4$, e.g. `0.0016%` at $p = 6\%$, while leaving a `6.25%` residual at a `50%` coin-flip flake).
     - *Repair's check & lane gate:* Pre-merge `flaky-*` still runs `1` time per [`OQ-TPF3`](#OQ-TPF3) (`1` pass lands; `1` fail returns to the fixer). Once re-enabled on `main`, even if an incomplete fix fails on its **very first** proof (before any post-enable `pass`), the `1` check on `tip` catches `fail + pass` (`94%` at $p = 6\%$) -> `flaky-<slug>-2` immediately instead of reverting the fix. In lane gates, `1` confirmation run on `base`/`head` acquits most trunk flakes without bouncing the worker.
     - *Sitting with "a red is read once, never re-run":* Preserves the substantive rule (`fail + pass` is `disabled` + `flaky-*`, never `pass`, and passing tests run once), while amending [`D-GR22`](../reference/gate.md#D-GR22) and [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) to authorize `1` same-tree reproducibility run on uncontradicted failures.
   - **C — Short concurrent diagnostic burst on uncontradicted failures (`K = 4` parallel `GOMAXPROCS=1` runs of the compiled test binary; any `pass` = flaky, `4 / 4` `fail` = broken).** Whenever a non-timeout test fails with no stored `pass` on its current inputs, compile `./<pkg>` once (`go test -c`) and run only that test `K = 4` times concurrently in isolated `GOMAXPROCS=1` workers (`~1x` single-test wall time, reproducing scheduler contention directly).
     - *Proof:* Catches both low-rate flakes (`0.0001%` false-broken at $p = 6\%$) and `50%` coin-flip or contention-only flakes (`(0.5)^5 = 3.1%` false-broken) right on `tip` in `~1x` single-test wall time, disabling the flake and advancing `refs/tillr/green`.
     - *Culprit bisection:* Virtually eliminates entering `SearchFirstRed` on a flake, and confirming a culprit `C` whose inputs differ from `tip` before auto-revert drives false culprit reverts below $p^{10}$.
     - *Repair's check & lane gate:* Pre-merge `flaky-*` **still requires only `1` pass** per [`OQ-TPF3`](#OQ-TPF3) (zero burst bar to land a fix). Only **after** a test fails without a stored `pass` on `main` (or in lane failure diagnosis) does the `4`-worker burst run — cleanly separating `"fails again in a flakey way"` (`>= 1` pass -> `flaky-<slug>-2`) from `"fix deterministically broke the test"` (`4 / 4` fail -> revert / `fixer-main`).
     - *Sitting with "a red is read once, never re-run":* Passing tests still run once and `pass` in the burst never turns a failed test green (`disabled` + `flaky-*`), while amending [`D-GR22`](../reference/gate.md#D-GR22) and [`gate-check-rules.md`](../reference/gate-check-rules.md#a-red-is-read-once-never-re-run) to allow a `K = 4` concurrent diagnostic burst on uncontradicted failures (introducing a fixed width parameter `K = 4`).
