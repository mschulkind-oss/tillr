# An open question goes in a new design document, never in a reference

**Status:** 2026-11-26, verified against `f9d19a2d899e`. None of the enforcement or prompt changes in this design is built: `rg -n 'referenceNoOpenQuestions|DesignReferenceRule' tools/` prints nothing, `rg -c 'empty — fill in when decided' docs/reference` and `rg -c -i 'awaiting\s+(the\s+)?owner' docs/reference` both exit `1` (after `659b8f38` and `e56645b0` folded the 2026-11-25 rulings into [`docs/reference/gate.md`](../reference/gate.md)), while [`docs/reference/gate.md`](../reference/gate.md) still carries `stage: DECIDED`, `planning-actions: none`, `next:`, and unbuilt specifications ([`OQ-GR4`](../reference/gate.md#OQ-GR4) / [`D-GR45`](../reference/gate.md#D-GR45), [`D-GR12`](../reference/gate.md#D-GR12), [`D-GR51`](../reference/gate.md#D-GR51)). Following the rule this document states ([§2](#2-the-standing-rule-and-where-authors-read-it-r-noq1-d-noq1)), this file is a standalone design under `docs/design/` linking [`docs/reference/gate.md`](../reference/gate.md), [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md), and [`docs/reference/tillr-designer-sessions.md`](../reference/tillr-designer-sessions.md), touching zero files under `docs/reference/` and zero shared index files.

> **In short.** A reference under `docs/reference/` describes what is built and holds no unanswered question, no ledger row awaiting the owner, and no unbuilt proposal. Whenever a new question or proposed change arises for a system that already has a reference, open a new design document under `docs/design/` that links the reference it changes; fold the result into the reference only after the design is ruled and built.

**Why it matters.** Parking open questions and unbuilt proposals inside `docs/reference/` turns evergreen system documentation into a live proposal surface, hides owner-blocking questions where readers expect verified truth, downgrades reference headers to `stage: DESIGN` and `status: in-review`, and concentrates concurrent edits onto one shared reference file ([§1.2](#12-how-docsreferencegatemd-drifted-and-why-vantage-check-missed-it)).

**The shape.** Four coordinated parts:

- Write the rule in the guides and `design`-seat brief surfaces authors read ([§2](#2-the-standing-rule-and-where-authors-read-it-r-noq1-d-noq1)).
- Extend the fast `documents` change check in [`tools/gate/change_common.go`](../../tools/gate/change_common.go) to refuse added unanswered questions, added `awaiting owner` ledger rows, and newly added or regressed non-reference frontmatter headers under `docs/reference/` ([§3](#3-the-gate-check-in-documents-d-noq2)).
- Update the workflow prompts, staging rules, and conflict, triage, and idea instructions that tell a `design` run where to write, while cataloging every remaining drift path ([§4](#4-briefs-workflow-prompts-and-every-other-drift-path-d-noq3)).
- Keep the trunk green on landing day via `base..head` diff evaluation while cleaning up [`docs/reference/gate.md`](../reference/gate.md) in an independent follow-up item ([§5](#5-what-happens-to-existing-open-questions-on-landing-day-d-noq4)).

**Cost.** One `git diff --name-status --no-renames` pass over `docs/reference/` inside the existing `documents` fast check (`0 ms` extra subprocesses when `docs/reference/` is untouched), plus opening a small standalone file under `docs/design/` whenever a built subsystem needs a new design decision.

**Start at [§2](#2-the-standing-rule-and-where-authors-read-it-r-noq1-d-noq1)** for the rule and its author surfaces, [§3](#3-the-gate-check-in-documents-d-noq2) for the `documents` gate check, and [§4](#4-briefs-workflow-prompts-and-every-other-drift-path-d-noq3) for the `design`-seat prompts and drift-entry matrix.

**Needs your ruling:** None. Owner ruling [`R-NOQ1`](#R-NOQ1) is settled; this document holds 4 designer's decisions from the filed operator request ([`D-NOQ1`](#D-NOQ1) through [`D-NOQ4`](#D-NOQ4) in the [Decision Ledger](#8-decision-ledger)), and the owner may overturn any of them.

**Reads with:** [`docs/reference/gate.md`](../reference/gate.md) (the reference where the drift occurred and whose cleanup [§5.2](#52-follow-up-cleanup-of-docsreferencegatemd) specifies), [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md) (where standing gate and document rules live once enforced), [`docs/reference/tillr-designer-sessions.md`](../reference/tillr-designer-sessions.md) (how review comments and designer desks route to documents), [`docs/tillr/decision-provenance-review.md`](../tillr/decision-provenance-review.md) ([`OQ-PR21` and `OQ-PR22`](../tillr/decision-provenance-review.md#6-how-this-stops-happening)), [`docs/design/tillr-watch/decision-record-files.md`](./tillr-watch/decision-record-files.md) (the sibling `base..head` check pattern in `documents`), and [`docs/design/tillr-review-rules.md`](./tillr-review-rules.md) (where prose-only reference compliance sits alongside mechanical gate checks).

## 2. The Standing Rule and Where Authors Read It ([`R-NOQ1`](#R-NOQ1), [`D-NOQ1`](#D-NOQ1))

### 2.1 The three-part lifecycle rule (`R-NOQ1`)

1. **A reference describes only what is built.** Every document under `docs/reference/` carries `status: accepted` and `stage: CURRENT`, describes behavior verified in the current tree, and holds **no unanswered question**, **no ledger row awaiting the owner**, and **no unbuilt proposal** (a documented known limitation states what the built code does not do today, never an unruled option list or an unbuilt specification). Historical owner rulings and settled engineering rationale that explain *why* built code works the way it does may stay in the reference's rationale table so code comments and designs have stable anchors, provided every row describes settled, built reality.
2. **A new question or proposed change opens a new design document.** When a question, owner trade-off, or unbuilt change arises for a subsystem that already has a document under `docs/reference/`, the author opens a **new standalone design document under `docs/design/`** whose frontmatter (`depends-on` or `related`) and opening prose link the `docs/reference/` document it proposes to change. The existing reference under `docs/reference/` is **not edited** to add the question, park a pending ledger row, or downgrade its `status` or `stage`.
3. **A built design folds into the reference.** Once the new design's open questions are ruled by the owner ([`OQ-PR21` and `OQ-PR22`](../tillr/decision-provenance-review.md#6-how-this-stops-happening)) and its implementation items have landed on the trunk, a graduation change folds the verified behavior and settled rulings into the target `docs/reference/` document (keeping `status: accepted` and `stage: CURRENT`), repoints any inbound links, and deletes (or marks `SUPERSEDED` / `GRADUATED` where kept for history) the graduated `docs/design/` file.

```text
new question or change on a built subsystem
        │
        ▼
open docs/design/<topic>.md (links docs/reference/<sys>.md; reference untouched)
        │
        ▼
owner rules OQs ──► build items land on trunk
        │
        ▼
fold verified behavior + settled rulings into docs/reference/<sys>.md (status: accepted, stage: CURRENT)
```

### 3.2 Exact three-clause `base..head` predicate

Inside `runChangeCheck("documents", ...)` in [`tools/gate/change_common.go`](../../tools/gate/change_common.go), immediately after `watchDecisionRecordFindings(root, base, head)` and **before** `judgeDocuments(root, head, documents)`, call `referenceNoOpenQuestionsFindings(root, base, head)`.

`referenceNoOpenQuestionsFindings` inspects committed Git blobs over `base..head` using `git diff --name-status --no-renames -z <base> <head> -- docs/reference`:

- **Rename handling (`--no-renames`):** Moving an unfinished design into `docs/reference/` (`git mv docs/design/x.md docs/reference/x.md`) appears as `D` on `docs/design/x.md` and `A` on `docs/reference/x.md`, so the destination is judged as a newly added reference. Deleted (`D`) paths under `docs/reference/` are ignored. When `base == head` or no `docs/reference/**/*.md` path has status `A`, `M`, or `T`, the helper returns `nil, nil` without reading blobs.
- **Fence stripping:** Before scanning body lines of `git show <rev>:<path>`, toggle fence state on lines whose left-trimmed prefix starts with ```` ``` ```` or `~~~` (closing only on a matching fence character, identical to `watchDTWAnchors` in [`tools/gate/change_common.go`](../../tools/gate/change_common.go)). Specimen Markdown inside fenced code blocks (for example in [`docs/reference/gate-check-rules.md`](../reference/gate-check-rules.md)) is never flagged.
- **Per-document extraction (`extractReferenceDrift(text string)`):** From a document's YAML frontmatter and non-fenced body lines, extract three deterministic sets/maps:
  1. **Unanswered question blocks (Clause 1, `c6`):**
     - Any Vantage question directive `<!--\s*vantage:\s*(?:question|oq)\b[^>]*-->` (keyed by `id=<ID>` when present, else normalized directive text) that is **not** answered — i.e., its question block carries no answered `✅` marker and `status=` (if present on the directive) is not `answered`, `decided`, `resolved`, or `closed`;
     - Any open or blocked question list/heading item outside tables matching `(?:💬|🔒)\s*(?:\*\*|\[)?\s*(OQ-[A-Za-z0-9_-]+)` (keyed by `<ID>`, or normalized line when unkeyed);
     - Unanswered answer-placeholder lines matching `(?i)\bempty\s*(?:—|--|-)\s*fill in when decided\b` (counted and keyed to the nearest preceding `OQ-[A-Za-z0-9_-]+` heading/item/directive outside fences when one precedes it, plus total placeholder count so adding an unkeyed placeholder is always caught).
     - *Added relative to `base`:* On an `A` file, every extracted unanswered question item is a violation. On an `M` or `T` file, any unanswered question key present at `head` and absent at `base`, or any increase in total unanswered placeholder lines (`head.placeholderCount > base.placeholderCount`), is a violation. Settled `OQ-*` anchors inside prose or inside `Answered open questions` / `Settled by the owner` tables (carrying no `💬`, `🔒`, unanswered Vantage directive, or `empty — fill in when decided` placeholder) are **never** matched.
  2. **Ledger rows marked as awaiting the owner (Clause 2, `c6`):**
     - Any non-fenced Markdown pipe-table row (`strings.HasPrefix(trimmed, "|")`, skipping `:---` separator rows) whose cells match case-insensitive `(?i)\bawaiting\s+(?:the\s+)?owner\b` or `(?i)\b(?:pending|needs)\s+(?:the\s+)?owner(?:'s)?\s+(?:ruling|decision|answer)\b`. Each matching row is keyed by its first cell's normalized identifier (stripping HTML `<a id="..."></a>` tags, backticks, brackets, and bold markers — e.g. `D-GR45` — or the full normalized row when the first cell is empty).
     - *Added relative to `base`:* Any awaiting-owner row key present at `head` and absent at `base` (or any increase in unkeyed awaiting-owner row count) is a violation. Pre-existing awaiting-owner rows in `base` pass when untouched or deleted, and fail if a new awaiting-owner row (`D-GR57 | ... | No; awaiting owner |`) is added.
  3. **Non-reference frontmatter headers (Clause 3, `c7`):**
     - Parse YAML frontmatter keys (`status`, `stage`, `next`, `planning-actions`) via `frontmatterEntries(text)` (already in `package main` in [`tools/gate/tree_common.go`](../../tools/gate/tree_common.go)).
     - On a newly added (`A`) file `docs/reference/**/*.md`: require `status == "accepted"`, `stage == "CURRENT"`, and neither `next` nor `planning-actions` set.
     - On a modified (`M` or `T`) file `docs/reference/**/*.md`: refuse if `status` changed to a value other than `"accepted"` (when `base` had `"accepted"` or a different value), if `stage` changed to a value other than `"CURRENT"`, or if `next` or `planning-actions` is present at `head` when absent at `base`. (If `base` already had `stage: DECIDED`, `planning-actions: none`, and `next: ...` — as [`docs/reference/gate.md`](../reference/gate.md) does at `f9d19a2d899e` — or `status: in-review` / `stage: DESIGN`, leaving those pre-existing header fields unchanged while fixing prose passes, and restoring them to `status: accepted` and `stage: CURRENT` while deleting `next` and `planning-actions` passes.)
