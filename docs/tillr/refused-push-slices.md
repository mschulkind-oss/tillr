# Refused-push repair: landing order

File one item per numbered slice, in order. The slices replace the single item that builds the rest of [Refused autopushes](../design/tillr-refused-push.md) (the request that reads "Build the rest of the refused-push design"): together they cover everything it asks, and each can be built and verified once. Slices 2 to 13 each change live behavior and are true on their own. Slices 14 to 21 build conflict repair without turning it on; slice 22 is the only one that turns it on. This division is the designer's proposal on the operator's request of 2026-11-21; the owner may overturn it.

## Rules for every slice

- **Donor, not checkout.** Files named below are donor files in the retained candidate. Bare filenames are in `tools/tillr-drain/drain/`; `land:` means `tools/tillr-land/land/`, `view:` means `tools/tillr-view/`. Take the named behavior only. A retained test that exercises the finished system is split or rewritten for the intermediate state.
- **Fence letters.** `D` is `tools/tillr-drain/` with its mirror `yolo-packs/tillr/files/local/share/tillr/tillr-drain/`; `L` and `V` are the same pair for `tillr-land` and `tillr-view`. Each source slice commits `just pack-sync` in the same commit.
- **Budget.** The cap on each slice counts source additions plus deletions, not tests, READMEs or the mirror. It is a filing cap, not a measurement of unwritten work.
- **Kept behavior.** Commit `8fe514714`'s clean replay is not rebuilt in any slice. `TestRefusedPushRebasesOntoTheMovedRemote` and `TestRefusedGreenPushHealsThroughTheAction` in `push_refused_test.go` stay byte-identical until slice 22 and pass in every slice that touches `push_refused.go` or `post_landing.go`.
- **Never.** No slice passes `+`, `--force` or `--force-with-lease` to `git push`, and none writes a merge commit on `main`.
- **README.** A slice that adds a state, a command or a ref updates the sentence that describes it in the module README it touches, in the same commit, and passes `uvx vantage-check` on that file.
- **Report.** Four verdicts refused the report alone (a6-c2, a7-c2, a9-c2, a15-c2). The report lists every verification command the run executed, with its exit status, including the first failing run of a test written before its fix.
- **Not in a lane.** The whole-suite check that reverted attempt 5 runs at the gate. A lane runs the tests named in its slice and every test in a file it edits.

## Items to file

Each entry gives: what to build, the donor, the fence and cap, **Accept** (the slice's own acceptance criteria, each with its test), **Closes** (the verifier findings it closes, by the IDs in the [findings table](#verifier-findings)), and **Needs** (slices that must have landed).

### The design, then the record

1. **Amend the design for three choices the build made (docs only).** The retained work and its verdicts rely on three things the design does not say. Each is the designer's decision, and the owner may overturn it; record each in the Decision Ledger as such.
   - **A fetch before a due push.** A due push first fetches the target ref and stops as `remote-rewritten` when the remote no longer contains the published pointer. This follows the operator's retry instruction of 2026-11-21 (*"a remote force-pushed back to an ancestor of the recorded published commit is silently re-published by an ordinary push in pushTrunk and PushOnce; guard that path and test the straight-backward case"*). It changes the non-goal sentence in [What this does not do](../design/tillr-refused-push.md#82-what-this-does-not-do), which says remote state is read only when a push is refused or `tillr drain push` runs: a fetch at a due push is not a timer poll, and the sentence should say so.
   - **Holds read from facts.** A hold (an open conflict repair, a rebased tip awaiting proof) is read from the fact that makes it true — the open item, the recorded rebased tip and the refs — and never from the newest push event.
   - **A cleared state.** A new state kind `remote-sync-cleared` records that a conflict hold ended because its repair item closed without landing; it shows no waiting row.

   **Fence:** `docs/design/tillr-refused-push.md`. **Accept:** the three decisions are in the ledger marked as the designer's; the non-goal sentence and [Step 2](../design/tillr-refused-push.md#32-step-2-fetching-the-target-ref-classifies-the-exact-commit-graph) agree with the first; the kinds table in [Waiting rows and named movers](../design/tillr-refused-push.md#71-waiting-rows-and-named-movers) names the third; `uvx vantage-check` passes on the file. **Closes:** none; it removes the contradiction that would send slices 4, 8 and 18 back with a `definition` obstacle. **Needs:** nothing.
